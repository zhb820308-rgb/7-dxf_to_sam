## 一、工程架构与接口定义 — 补充

### [功能点 S1] 依赖管理与构建脚本
- **优先级：** 高 | **建议迭代：** MVP

原文档提到了引入 DXF 解析库，但未明确构建系统与依赖管理方式：
- 使用 **CMake** 作为统一构建系统，编写 `CMakeLists.txt`，支持 MSVC、GCC、Clang 三套工具链。
- 将第三方依赖（dxflib / LibreDWG）以 **FetchContent** 或 **git submodule** 方式管理，避免手动拷贝和版本不一致。
- 编写 `vcpkg.json` 或 `conanfile.txt`，实现一键安装所有依赖。
- 提供 `build.bat` / `build.sh` 脚本，降低新成员环境配置成本。

### [功能点 S2] 配置文件系统
- **优先级：** 中 | **建议迭代：** 第二迭代

原文档将容差、角度步长等作为命令行参数，但缺少持久化配置：
- 定义 `config.json` 或 `config.ini` 文件，统一管理：
  - 离散化参数：容差（Tolerance）、角度步长（AngleStep）、最大递归深度
  - 输出参数：坐标精度（小数位数）、坐标系缩放因子、默认输出格式
  - 日志参数：日志级别、输出路径、文件大小轮转
- 实现 `ConfigManager` 单例类：
  - 支持从文件加载、命令行参数覆盖、运行时修改
  - 提供合理默认值，保证零配置也能运行
- 支持 `--config` 参数指定自定义配置文件路径

## 二、DXF 文件读取与预处理 — 补充

### [功能点 S4] 文件编码与特殊字符处理
- **优先级：** 中 | **建议迭代：** 第二迭代

- DXF 文件可能存在 **GBK / Shift-JIS / UTF-8** 等多种编码，特别是中/日/韩文图层名和注释：
  - 在读取文件头时检测编码（BOM 标记或内容启发式判断）
  - 实现 `EncodingConverter` 工具类，统一转为 UTF-8 内部处理
  - 对无法识别的编码提供 fallback 机制和警告日志
- 处理文件名和路径中的特殊字符（空格、Unicode 字符）

### [功能点 S5] DXF 异常数据容错
- **优先级：** 高 | **建议迭代：** MVP / 第一迭代

现实中的 DXF 文件常带有不规范数据：
- **缺失字段：** 某些实体缺少必要参数时，使用默认值替代并记录警告
- **无效几何：** 零长度直线、半径为零的圆弧、退化多边形 → 跳过并记入 `skipped_entities.log`
- **无限循环防护：** 图块嵌套深度超过阈值（如 32 层）时强制终止递归，输出错误上下文
- **损坏文件恢复：** 尝试读取可解析的部分，而非直接崩溃（"尽力解析"策略）
- 实现 `ErrorRecovery` 类，统计跳过实体数量，在最终报告中展示

### [功能点 S6] 大文件分块读取与进度回调
- **优先级：** 中 | **建议迭代：** 第三迭代

- 对于超过 100MB 的大型 DXF 图纸：
  - 采用**流式解析（SAX 风格）**而非一次性加载到内存
  - 解析进度通过回调函数上报 `(currentPos, totalSize, entityCount)`
  - GUI 模式下更新进度条；控制台模式下打印百分比
- 支持 `--max-file-size` 参数，超限时给出明确提示是否继续

## 三、几何离散化与转换 — 补充

### [功能点 S7] 图元去重与合并优化
- **优先级：** 高 | **建议迭代：** 第二迭代

离散化后可能产生大量冗余顶点：
- **共线点剔除：** 对同一线段上的中间点进行 Douglas-Peucker 简化
- **重合点合并：** 容差范围内的重复坐标合并为单一点
- **首尾相连线段合并：** 同图层、同颜色、端点在容差内的连续线段合并为一条多段线
- 提供去重前后的点数量对比统计，便于验证质量

### [功能点 S8] 离散化质量评估工具
- **优先级：** 中 | **建议迭代：** 第二迭代

- 对每条离散化后的多段线计算**最大偏差（Max Deviation）**和**平均偏差**
- 与原始曲线叠加对比，生成可视化误差报告（可选输出为 SVG/CSV）
- 提供 `--quality-report` 开关，开启后输出每个实体的离散化质量指标
- 验收标准建议：最大偏差不超过设定容差的 1.5 倍

### [功能点 S9] 椭圆与椭圆弧支持
- **优先级：** 中 | **建议迭代：** 第二迭代

原文档覆盖了 LINE、LWPOLYLINE、ARC、CIRCLE、SPLINE，但未提及：
- **ELLIPSE 实体：** 船舶图纸中常见椭圆形舱口、舷窗
  - 解析参数：中心点、长半轴、短半轴、旋转角、起始/终止参数
  - 离散化策略：按角度步长采样参数方程
- 考虑使用与 ARC 类似的离散化基类，复用代码

### [功能点 S10] 多段线宽度与线型处理
- **优先级：** 低 | **建议迭代：** 第三迭代

- DXF 多段线可能包含**起点宽度**和**终点宽度**信息（用于表示变宽线条）：
  - 在 `CadEntity` 中增加可选字段 `startWidth` / `endWidth`
  - 输出到 SAM 时，用连续多边形模拟变宽线条效果
- 线型（实线、虚线、点划线）的元数据传递给 SAM，帮助还原图纸样式

## 四、统计与分类模块 — 补充

### [功能点 S11] 按图层/颜色/线型的多维度统计
- **优先级：** 中 | **建议迭代：** 第二迭代

原文档的统计仅针对图元类型，缺少业务视角：
- **按图层统计：** `图层"甲板"：直线 45条，圆弧 12条，占比 23%`
- **按颜色统计：** `红色(1号色)实体 67个，蓝色(5号色)实体 34个`
- **按几何复杂度统计：** `简单实体(≤4顶点) 120个，复杂实体(>4顶点) 80个`
- 输出格式支持 **CSV / JSON**，方便导入 Excel 做进一步分析

### [功能点 S12] 数据一致性校验报告
- **优先级：** 中 | **建议迭代：** 第二迭代

- **连通性检查：** 检测离散化后的线段端点是否形成封闭区域（对船体截面重要）
- **范围检查：** 检测坐标范围是否在合理区间（防止坐标单位误读，如 mm vs m）
- **重叠检测：** 发现高度重叠的线段，提示可能的重复导入问题
- 输出 `validation_report.json`，包含每条检查的通过/失败状态

## 五、SAM 软件对接接口层 — 补充

### [功能点 S13] 多种输出格式支持
- **优先级：** 中 | **建议迭代：** 第二迭代

原文档提到了 JSON / TXT / SCR / Python 等方案，可进一步明确：
- **JSON 格式（通用中间格式）：**
  ```json
  {
    "version": "1.0",
    "metadata": { "sourceFile": "ship.dxf", "entityCount": 350 },
    "entities": [
      { "id": 1, "layer": "甲板", "color": [255,0,0],
        "type": "polyline", "points": [[x1,y1,z1],[x2,y2,z2],...] }
    ]
  }
  ```
- **OBJ 格式：** 将离散化线段作为边（Edge）输出，兼容主流 3D 软件
- **CSV 坐标集：** 每行一个点，适合 Python 脚本二次处理
- **自定义二进制格式：** 针对超大数据集（10万+线段）优化读写速度
- 通过 `--output-format` 参数指定，插件式架构便于新增格式

### [功能点 S14] SAM 软件版本适配与回退
- **优先级：** 中 | **建议迭代：** 第三迭代

- 调研目标 SAM 软件的版本号及其支持的脚本/API 差异
- 建立**版本适配矩阵**：
  | SAM 版本 | 支持格式 | API 方式 | 注意事项 |
  |---------|---------|---------|---------|
  | v3.x    | .scr, Python | API v2 | 推荐方式 |
  | v4.x    | .scr, JSON   | API v3 | 格式变更说明 |
- 自动检测 SAM 版本或通过 `--sam-version` 手动指定
- 当目标版本不支持某项功能时，自动降级并给出提示

### [功能点 S15] 通信超时与重试机制
- **优先级：** 中 | **建议迭代：** 第三迭代

- 若采用嵌入式 API 或进程间通信方式调用 SAM：
  - 设置合理的超时时间（默认 30 秒）
  - 实现指数退避重试策略（3 次重试，间隔 1s → 2s → 4s）
  - 超时后输出详细的通信日志，辅助排查问题
  - 提供 `--dry-run` 模式：仅生成中间文件，不实际调用 SAM

## 六、功能集成与交互界面 — 补充

### [功能点 S16] 批量处理的并发控制
- **优先级：** 中 | **建议迭代：** 第三迭代

原文档提到了批量文件处理，但未涉及性能策略：
- **多线程批量处理：** 使用 `std::thread` 或 `std::async` 池，同时处理 4~8 个文件
- 每个文件独立处理管线，避免共享状态竞争
- **资源限制：** `--max-concurrent` 参数控制并发数，防止内存溢出
- **汇总报告：** 批量完成后生成 `batch_summary.csv`，列出每个文件的处理状态、用时、实体数量
- 支持 `--resume` 模式：从上次中断处继续处理，避免重复劳动

### [功能点 S17] 日志轮转与远程日志
- **优先级：** 低 | **建议迭代：** 第三迭代

- 实现日志文件自动轮转（按大小/按日期）
- 支持 **Flush 策略**：每条日志/每隔 N 条强制写入，防止崩溃时丢失
- 增加 **Telemetry**（可选）：遇到崩溃时自动输出 dump 文件和错误上下文
- 支持 **syslog / UDP 远程日志**（进阶）：方便集成到企业级监控系统

### [功能点 S18] 交互式预览
- **优先级：** 低 | **建议迭代：** 第三迭代

- 在 GUI 或命令行中增加**简单 ASCII/OpenCV 预览**功能：
  - 将离散化结果渲染为简单的 2D 缩略图（使用 SVG 或 ASCII art）
  - 标注关键实体数量、图层分布
  - 支持 `--preview` 参数快速查看结果，无需启动 SAM
- 使用 Qt Widget 或 QGraphicsView 实现缩放/平移查看
- 高亮显示离散化偏差较大的区域（超过容差 2 倍时标红）

## 七、测试与质量保障 — 新增模块

### [功能点 T1] 单元测试体系
- **优先级：** 高 | **建议迭代：** MVP / 第一迭代

- 引入 **Google Test** 或 **Catch2** 测试框架
- **核心算法测试覆盖：**
  - 圆弧离散化：输入标准圆弧，验证输出点数量与最大偏差
  - 样条离散化：输入已知样条，验证拱高不超过设定容差
  - 图块展开：输入嵌套图块，验证展开后实体数量与类型正确性
- **边界条件测试：**
  - 空文件、只有注释的 DXF
  - 超大坐标值（接近 double 精度极限）
  - 极度扭曲的样条曲线
  - 零长度直线 / 满圆圆弧 / 退化椭圆
- 编写 CI 配置文件（`.github/workflows/ci.yml`），每次推送自动运行测试

### [功能点 T2] 基准测试与性能回归
- **优先级：** 中 | **建议迭代：** 第二迭代

- 使用 **Google Benchmark** 建立性能基准测试：
  - 解析不同大小 DXF（1K/10K/100K 实体）的耗时
  - 离散化 1000 条样条曲线的平均耗时
  - 多线程批量处理的加速比
- 在 CI 中加入性能回归检测，对比每次提交的性能变化
- 输出 `benchmark_report.md` 记录各版本性能数据

### [功能点 T3] 集成测试套件
- **优先级：** 高 | **建议迭代：** 第一迭代 / 第二迭代

- 准备**标准测试 DXF 文件集**（从简单到复杂，涵盖船舶图纸特征）：
  - `test_simple.dxf`：仅含直线和圆
  - `test_arcs_splines.dxf`：圆弧和样条曲线组合
  - `test_blocks_nested.dxf`：多层嵌套图块
  - `test_ship_sample.dxf`：真实船舶图纸（脱敏后）
  - `test_malformed.dxf`：含错误数据的异常文件
- 为每个测试文件编写预期的验收标准（实体数量 / 离散化偏差阈值）
- 集成测试脚本自动运行全部用例，输出 PASS/FAIL 结果

### [功能点 T4] 内存使用监控
- **优先级：** 低 | **建议迭代：** 第三迭代

- 对大型文件处理过程进行内存追踪：
  - 在关键步骤记录内存峰值（解析前 / 解析后 / 离散化后 / 输出生成后）
  - 当内存占用超过阈值时发出警告
  - 输出 `memory_profile.json` 辅助优化
- 使用 `Valgrind`（Linux）或 `Dr.Memory`（Windows）检测内存泄漏

## 十、风险与应急预案 — 新增模块

### [功能点 R4] 技术风险清单
| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| dxflib/LibreDWG 无法解析特定版本 DXF | 中 | 高 | 预留替换库的接口抽象层；实现双库切换策略 |
| 样条离散化算法在高精度下性能不足 | 中 | 中 | 实现自适应步长优化；必要时启用 GPU 加速 |
| SAM 软件 API 变更不兼容 | 低 | 高 | 输出层与业务层严格解耦；优先使用通用中间文件 |
| 超大图纸（>500MB）导致内存溢出 | 中 | 中 | 实现流式解析；引入分块处理机制 |
| 中文路径/图层名乱码 | 中 | 中 | 统一 UTF-8 内部编码；覆盖多种编码测试 |

### [功能点 R5] 用户反馈与遥测（可选）
- **优先级：** 低 | **建议迭代：** 第三迭代

- 在用户允许的情况下，收集匿名使用数据：
  - 处理的 DXF 文件大小分布
  - 常用参数配置
  - 崩溃日志与堆栈
- 不收集图纸内容或用户个人信息
- 通过 `--no-telemetry` 开关完全禁用
