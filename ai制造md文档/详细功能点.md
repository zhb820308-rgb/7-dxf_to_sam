
# DXF 导入与 SAM 三维渲染项目开发计划书

> **项目目标：** 使用 C++ 开发一个 DXF 文件导入工具，读取船舶 CAD 图纸，将复杂曲线自动离散化为多线段，并生成可供 SAM 软件三维渲染的数据。
> **技术栈：** C++, dxflib (或 LibreDWG), STL,  Qt

---

## 一、 项目概述与需求分解

根据任务要求，本项目的核心工作流如下：
`DXF 文件输入` -> `DXF 解析` -> `图元分类与几何离散化` -> `统计报告生成` -> `SAM 接口数据生成` -> `三维渲染`。

### 核心难点

1. **船舶图纸的特殊性：** 包含大量嵌套图块（Block）和多阶样条曲线（Spline）。
2. **曲线离散化：** 需编写可靠的 C++ 数学算法，将圆弧和样条曲线按指定容差切割为多线段。
3. **数据对接：** 将解析出的 C++ 几何数据，转化为 SAM 软件能读取的中间文件或 API 调用。

---

## 二、 详细功能点拆解 (WBS)

项目共划分为 **6 大模块**，包含 **20 个开发功能点**，建议按模块顺序依次迭代开发。

### 模块一：工程架构与接口定义 (准备阶段)

> 目标：搭建基础开发环境，定义统一的数据结构，确保后续模块的松耦合。

* **[功能点 1] 项目环境搭建与依赖引入**
  * 配置 C++ 编译器（MSVC / GCC / Clang）。
  * 引入第三方 DXF 解析库（如 `dxflib` 或 `LibreDWG`），确保编译通过。
* **[功能点 2] 定义统一的数据结构 (DTO)**
  * 定义 `struct CadPoint { double x, y, z; };`
  * 定义 `struct CadEntity { int type; int layerId; int color; std::vector<CadPoint> points; };`
  * 作用：屏蔽不同 DXF 解析库的差异，建立内部统一标准。
* **[功能点 3] 日志与错误处理系统**
  * 编写日志管理类（如 `Logger`），支持不同级别的信息输出（Info, Warning, Error），方便后期调试。

### 模块二：DXF 文件读取与预处理 (输入层)

> 目标：将 DXF 文件解析为 C++ 内存中的原始几何对象。

* **[功能点 4] DXF 文件有效性校验**
  * 检查文件路径合法性及文件后缀（.dxf）。
  * (进阶) 读取文件头，检测 DXF 版本（如 R2010, R2018），对过于新潮的格式给出友好提示。
* **[功能点 5] 基础图元解析**
  * 调用解析库的回调函数，提取基础图元：直线 (`LINE`)、轻量多段线 (`LWPOLYLINE`)、圆弧 (`ARC`)、圆 (`CIRCLE`)。
  * 提取对应的几何参数（起点/终点坐标、圆心/半径等）。
* **[功能点 6] 图块 (Block) 处理与炸开 (Explode)**
  * **核心难点：** 递归读取 DXF 中的 `BLOCK` 和 `INSERT` 记录。
  * 将嵌套的图块“炸开”为最底层的 `LINE` 和 `ARC` 实体，防止形成孤立对象。
* **[功能点 7] 图层、颜色、线型元数据解析**
  * 解析 DXF 的 `LAYER` 表，将图层 ID 与实体关联，并获取每个图层对应的 RGB 颜色值。此数据将用于在 SAM 中还原图纸的色彩。

### 模块三：几何离散化与转换 (算法核心层)

> 目标：满足需求中“曲线自动转成多段线”的要求，为 SAM 渲染提供标准点集。

* **[功能点 8] 圆弧/圆转多线段算法**
  * 编写 C++ 数学算法，根据用户设定的**角度步长**（如 5度），在 `ARC` 和 `CIRCLE` 上取样，生成连续的折线集合。
* **[功能点 9] 样条曲线 (Spline/NURBS) 离散化算法**
  * **核心难点：** 实现**递归细分算法**或基于**容差 (Tolerance)** 的采样。
  * 逻辑：判断曲线段的“拱高”是否超过设定的阈值（如 0.1mm）。若超过，则在该点处一分为二，递归处理，直至满足容差。
* **[功能点 10] 统一重建模型**
  * 将解析出的直线，以及由圆弧/样条转换出的多段线，全部统一存入 `std::vector<CadEntity>` 容器中。此时，工程图完全变成了“点阵”线段集。

### 模块四：统计与分类模块

> 目标：满足需求中“统计有多少类型曲线”的要求。

* **[功能点 11] 原始图元统计**
  * 生成解析报告：`原始数据：直线 120条，圆弧 50条，样条曲线 20条...`
* **[功能点 12] 转换后图元统计**
  * 生成最终数据报告：`转换后：共 190 段多线段（由直线及平滑曲线离散化生成）。`
* **[功能点 13] 输出日志文件**
  * 将统计数据保存至本地 `report.log`，方便与 CAD 软件原生统计进行对照验证。

### 模块五：与 SAM 软件对接的接口层

> 目标：将 C++ 中的几何数据传递给 SAM 软件。

* **[功能点 14] 三维空间坐标映射**
  * 处理 DXF 二维坐标系与 SAM 三维坐标系的映射（X,Y 对应 X,Y,Z=0），处理图纸比例尺（Scale）的缩放转换。
* **[功能点 15] SAM 渲染数据生成器**
  * **方案 A：** 生成通用的中间格式文件（如 JSON、TXT 坐标集），供 SAM 读取。
  * **方案 B：** 生成 SAM 能识别的脚本（如 SAM 的 `.scr` 命令流文件或 Python 脚本）。
* **[功能点 16] 嵌入式 API 调用 (可选/进阶)**
  * 如果 SAM 支持 C++ SDK/DLL，则直接在此处调用接口，如 `samAPI->DrawLine(pointA, pointB)`，实现实时的三维模型绘制。

### 模块六：功能集成与交互界面 (应用层)

> 目标：提供用户可操作的程序入口。

* **[功能点 17] 控制台参数解析器**
  * 支持命令行调用：`DxfToSam.exe --input ship.dxf --tol 0.5`
* **[功能点 18] 图形界面 (GUI) 开发 (可选)**
  * 使用 Qt 或 MFC 开发简易 EXE，包含“选择文件”、“开始转换”按钮及统计结果展示框。
* **[功能点 19] 批量文件处理支持**
  * 允许用户拖拽文件夹，程序自动遍历目录下所有 `.dxf` 文件并进行批处理。
* **[功能点 20] 最终集成测试与验收**
  * 使用企业级的船舶 CAD 图纸进行实际测试。在 SAM 中对比渲染效果，验证没有出现线条缺失、乱码或坐标偏移。

## 三、 迭代开发与交付建议 (R&D Roadmap)

为了保证交付速度和成功率，建议采用 **MVP（最小可行性产品）** 的方式进行迭代：

### 🟢 第 1 迭代：核心管线打通 (MVP)

* **涉及功能：** 1, 2, 3, 4, 5, 8, 10, 11, 13, 17
* **交付物：** 一个黑框 C++ 控制台程序。能读取最简单的 DXF（只有直线和圆），能将其转为坐标点，能输出一个简单的数据文件给 SAM，并成功画出东西。

### 🔵 第 2 迭代：突破难点 (复杂图纸支持)

* **涉及功能：** 6, 7, 9, 12
* **交付物：** 解决了图块嵌套问题，攻克了样条曲线（Spline）离散化数学算法。能成功加载真实的船舶图纸（包含曲线和复杂图块）。

### 🟣 第 3 迭代：产品化 (易用性完善)

* **涉及功能：** 14, 15, 18, 19, 20
* **交付物：** 完成 GUI 界面的封装（或制作了完备的命令行批处理功能），自动带上图层颜色，输出最终的统计表格，完成最终的交付验收。
