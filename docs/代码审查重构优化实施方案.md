# DXF-to-SAM 代码审查、重构与优化实施方案

## 1. 文档目的

本文档用于指导当前 DXF-to-SAM 项目完成一轮可验证、可回退的代码审查、重构与性能优化。

整体流程：

```text
建立行为基线
→ 五维代码审查
→ 补充回归测试
→ 小步重构
→ 数据驱动的性能优化
→ 最终复审与 SAM 验收
```

本轮工作的基本原则：

- 正确性和数据完整性优先于代码风格。
- 重构必须保持现有行为，功能变化应单独实施。
- 先用测试固定行为，再修改复杂实现。
- 每批变更保持小而独立，建议控制在约 100～300 行。
- 性能优化必须提供优化前后的测量数据。
- 不确定是否为死代码时，先列出并确认，不直接删除。

4. 安全性：不可信输入、路径和 URL、密钥、资源限制和异常泄露。
5. 性能：算法复杂度、容器分配、同步 IO、事件循环和大对象复制。

## 7. 阶段四：小步重构

### 7.1 批次一：统一结果和错误模型

目标：消除整数返回值与错误字符串共同控制流程的脆弱实现。

建议定义明确状态：

```cpp
enum class ImportStatus
{
    Success,
    Canceled,
    ParseFailed,
    ConvertFailed,
    BeginFailed,
    CreateFailed,
    CommitFailed
};
```

要求：

- 每个创建阶段结束后立即检查结果。
- 取消和失败不得继续创建或提交。
- 日志文案与程序状态解耦。
- Sketch 与 FE 模式采用一致的结果语义。

### 7.2 批次二：拆分 DXF 解析职责

建议将以下职责从大型解析文件中分离：

- libdxfrw 实体回调。
- 原始实体校验与转换。
- 块定义存储。
- INSERT 变换构建。
- 块递归展开和循环检测。

嵌套 INSERT 使用统一齐次仿射矩阵组合：

```text
块基点平移
→ 缩放
→ 旋转
→ 阵列偏移
→ 插入点平移
```

不再依赖简单的角度相加和比例相乘表达全部嵌套变换。

### 7.3 批次三：简化 Python 绑定

`Example1PytModule.cpp` 只保留：

- Python 参数解析。
- 调用应用服务。
- 将结构化结果转换为 Python 返回值。

以下逻辑移入独立导入服务：

- 文件和参数校验。
- Parser、Converter、Builder 编排。
- 取消和失败状态传播。
- 日志生命周期。
- Sketch/FE 模式选择。

### 7.4 批次四：整理数据和几何层

- 为实体类型明确合法性约束。
- 使用 guard clause 降低嵌套层数。
- 合并重复条件和近似辅助函数。
- 为关键容差和常量提供统一来源。
- 明确 POINT 当前是支持、跳过还是不支持。
- 保留必要的数值防御和错误处理。

### 7.5 批次五：整理构建系统

- 将全局 include、definition 和 link 配置逐步改为目标级配置。
- 评估用明确源文件列表替代宽泛 `file(GLOB)`。
- 抽取测试公共库，减少每个测试重复编译同一源码。
- 保持依赖路径可配置，避免新增开发机绝对路径。
- 添加适合当前 MSVC/C++17 环境的警告级别。

### 7.6 批次六：拆分 Web 代码

在不引入新框架和构建器的前提下，将 `page/app.js` 拆分为：

- 页面状态管理。
- DXF 文件导入。
- 画布渲染与视口。
- 图元选择和编辑操作。
- Agent 请求和工具结果应用。
- UI 事件绑定和消息显示。

`server.js` 可按职责拆分为：

- HTTP 路由和响应。
- 请求体与输入校验。
- 几何工具实现。
- OpenAI 兼容接口调用。
- 静态文件服务。

### 7.7 批次七：GUI 和日志生命周期

- 核对 Qt 父子对象所有权。
- 仅替换真正不清晰或有风险的手动资源管理。
- 统一日志加载开始、取消、完成和销毁路径。
- 避免 UI 线程中无界同步读取。
- 保持日志过滤和显示行为不变。

## 8. 阶段五：性能优化

### 8.1 性能基准字段

每次基准运行记录：

```text
文件名和文件大小
导入模式
原始实体数量
BLOCK 和 INSERT 数量

转换耗时
SAM 创建耗时
总耗时
峰值内存
取消响应时间
最终包围盒
```

### 8.2 优先调查热点

- BLOCK/INSERT 重复变换和临时容器。
- 曲线离散过程中的动态分配。
- FE 节点合并算法复杂度。
- 大量实体的日志格式化和输出。
- Qt 进度回调和事件处理频率。
- Web 画布大图重绘。
- Node.js 大数组复制和 JSON 序列化。

### 8.3 优化准入条件

只有满足以下条件才实施优化：

- 基准数据证明该路径是实际热点。
- 优化不会降低数值正确性或取消响应能力。
- 优化前后使用相同输入和环境比较。
- 所有测试通过，关键几何输出一致。

## 12. 第一项建议任务

第一项建议执行的具体任务是：

> 审查当前 `DxfParser`、`DxfData` 和 `SamBuilder` 的实际实现，同时为 BLOCK/INSERT 与取消流程补充回归测试。

原因：

- BLOCK/INSERT 是当前几何链路中复杂度最高的部分。
- 几何错误可能不会导致导入失败，只会产生错误模型。
- 取消后部分提交会直接影响用户数据完整性。
- 坐标级测试建立后，才能安全进行结构性重构。
- 这些问题的收益高于单纯进行格式和命名整理。
