## 2. 阶段定义

本项目历史文档中存在多个“第四阶段”定义。当前阶段四统一以[代码审查重构优化实施方案](./代码审查重构优化实施方案.md)中的“阶段四：小步重构”为准。

阶段四的核心目标是：

> 在阶段三回归基线保护下，逐步降低 DXF 导入链路的职责耦合和维护成本，统一错误、取消和事务语义，同时保持 Sketch、Finite Element、Web 编辑器及现有 Python API 的外部行为不变。

阶段四不是一次整体重写，也不是性能专项。任何批次都必须能够独立构建、独立测试、独立回退。

## 5. 重构原则

1. **行为保持**：不改变当前支持的 DXF 图元、坐标结果、离散规则和 FE 拓扑。
2. **接口兼容**：`Example1.importDxf()` 的既有调用方式和成功返回值保持兼容。
3. **一次一个主题**：每个批次只处理一个明确职责，不混入性能优化或新功能。
4. **测试先行**：先用现有测试固定行为，必要时补充特征测试，再修改结构。
5. **失败即停止**：任何阶段失败或取消后，不得继续创建或提交。
6. **可回退**：每批修改可单独撤销，不依赖后续批次才能恢复构建。
7. **依赖单向**：Python/GUI 入口依赖应用服务，应用服务依赖解析、转换和 Builder 抽象，核心数据和几何层不反向依赖 GUI。
8. **不为拆分而拆分**：只有职责、测试边界或所有权得到改善时才新建文件。

## 8. P4-1：统一结果、错误和取消模型

### 8.1 目标

消除布尔值、整数、错误字符串和日志文本共同控制流程的情况，使所有导入阶段拥有明确、可测试的状态。

### 8.2 建议模型

Builder 层可以继续使用现有 `ImportBuildStatus`，但应用层结果至少需要区分：

```cpp
enum class DxfImportStatus
{
    Success,
    Canceled,
    ValidationFailed,
    ParseFailed,
    ConvertFailed,
    BeginFailed,
    CreateFailed,
    CommitFailed,
    RollbackFailed
};
```

应用层结果建议包含：

```text
status
errorCode
stage
message
createdCount
rollbackAttempted
rollbackSucceeded
```

不要求直接照搬以上字段名，但必须能明确表达“主操作失败且回滚也失败”的组合结果，不能让回滚错误覆盖原始错误。

### 8.3 工作内容

- 评审 `ImportBuildResult` 与 `DxfImportOutcome` 的职责边界。
- 统一 Sketch 与 FE 的 begin/create/commit/rollback 状态映射。
- 取消状态不得映射成普通失败。
- 参数、解析、转换和创建错误使用稳定错误码；日志文案不参与流程判断。
- 保持 Python API 兼容：成功仍返回当前数量，失败/取消仍按既有方式返回；结构化结果先供内部编排和测试使用。
- 对每个状态增加映射测试和日志断言。

### 8.4 重点测试

- validation、parse、convert、begin、create、commit 分别失败。
- 节点创建和 Truss 创建分别取消。
- 主操作失败、rollback 成功。
- 主操作失败、rollback 失败。
- rollback 重复调用的幂等性。
- 失败或取消后绝不调用后续 create/commit。

### 8.5 完成标准

- [ ] 所有导入阶段都有唯一、稳定的状态表示。
- [ ] Sketch 与 FE 使用相同的状态语义。
- [ ] 日志文本修改不会改变程序控制流。
- [ ] 原始错误和回滚错误均可追溯。
- [ ] Python 既有调用方式保持兼容。

## 9. P4-2：收口应用服务与 Python 绑定

### 9.1 目标

让 Python 入口只负责参数适配，让导入流程由独立、可测试的应用服务编排。

### 9.2 目标依赖关系

```text
Example1PytModule
    ↓ 参数适配
DxfImportOrchestrator / ImportService
    ├─ Validation
    ├─ Parser
    ├─ Sketch Conversion 或 FE Conversion
    ├─ BuildService
    └─ Session / Progress / Feedback / Logger
```

### 9.3 工作内容

- 核对 `Example1PytModule.cpp` 是否只保留参数读取、调用服务和返回值转换。
- 为 `DxfImportRequest` 明确默认值来源，避免 GUI、Python 和服务层各自维护常量。
- 将模式选择、图层解析和参数校验放在创建任何 SAM 对象之前。
- 将 Sketch/FE 公共流程收敛到同一应用服务，不强行合并两种转换器和 Builder。
- 将弹窗反馈与纯流程状态分离，使服务级测试不依赖真实 GUI。
- 控制编排器规模；当某段流程可独立测试且职责稳定时再提取函数或服务。

### 9.4 完成标准

- [ ] Python 绑定不直接编排 Parser、Converter 和 Builder。
- [ ] GUI 与 Python 入口使用相同的导入服务和参数规则。
- [ ] 服务级测试无需启动 SAM GUI 即可覆盖主要失败路径。
- [ ] 默认参数和错误映射只有一个权威来源。

## 10. P4-3：收口 Parser 与 BLOCK/INSERT 职责

### 10.1 目标

降低 `DxfParser` 的职责密度，同时保持阶段三已经固定的坐标、预算和递归行为。

### 10.2 推荐职责边界

| 模块 | 职责 |
|---|---|
| `DxfParser` | 文件解析生命周期、libdxfrw 接入、错误汇总 |
| 实体适配/校验模块 | 回调数据校验、原始 DXF 对象构造 |
| `DxfBlockExpansion` | BLOCK 存储读取、INSERT 递归展开、循环检测、预算消费 |
| 变换模块 | 统一二维/三维仿射变换构建、组合和点变换 |
| `DxfData` | 保存解析结果和统计，不承担流程编排 |

### 10.3 工作内容

- 审查 `DxfParser`、`DxfBlockExpansion`、`DxfEntityValidation` 当前边界。
- 清理重复校验和重复变换辅助函数。
- 保持统一仿射矩阵组合，不退回“角度相加、比例相乘”表达复杂嵌套变换。
- 预算、递归深度和循环引用错误继续通过结构化错误返回。
- 让块展开模块通过明确输入输出工作，减少对 Parser 内部可变状态的隐式依赖。
- 不在本批次改变曲线离散算法和实体支持范围。

### 10.4 必须保持的阶段三不变量

- 嵌套 INSERT、旋转、镜像、非均匀缩放坐标不变。
- 行列阵列坐标和数量不变。
- Z 坐标传播不变。
- 循环引用和深度上限仍能快速失败。
- 实体及块实例累计预算不被绕过。
- Web 和 C++ 三个样例的几何指纹不变。

### 10.5 完成标准

- [ ] Parser、实体适配、变换和块展开边界清晰。
- [ ] 没有新增重复的仿射变换实现。
- [ ] 坐标级和预算级测试全部通过。
- [ ] 大型真实图纸输出与阶段三基线一致。

## 11. P4-4：整理数据和几何层

### 11.1 目标

明确实体合法性、容差来源和 POINT 语义，降低分支嵌套和重复数值判断。

### 11.2 工作内容

- 为 POINT、LINE、CIRCLE、ARC、LWPOLYLINE、ELLIPSE、SPLINE 明确最小合法条件。
- 将常用有限数值、近似相等、零长度和容差检查集中到合适的公共模块。
- 统一曲线容差、节点合并容差和输出预算的默认值及边界。
- 使用 guard clause 简化无效数据、退化几何和预算失败路径。
- 明确 POINT 的产品行为：
  - Sketch 模式：当前解析但不创建；
  - FE 模式：创建独立节点但不创建 Truss；
  - 日志和统计必须准确反映这一差异。
- 保持父实体编号、来源类型和离散线段序号等可追溯信息。

### 11.3 完成标准

- [ ] 每种实体的合法性规则可以在测试中直接验证。
- [ ] 关键容差和上限没有相互冲突的重复定义。
- [ ] POINT 在 Sketch、FE、日志和统计中的语义一致且有文档说明。
- [ ] 几何输出数量、坐标、拓扑和误差不变。

## 17. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 结构化状态改变 Python 返回行为 | 现有脚本失效 | 增加 API 兼容测试，绑定层保持原返回约定 |
| Parser 拆分改变嵌套变换顺序 | 几何坐标错误 | 使用阶段三坐标级测试和三份样例指纹比较 |
| Builder 接口调整削弱 rollback | 取消或失败后残留对象 | 注入失败测试 + SAM GUI 同名重试 |
| Qt 所有权调整导致双重释放 | SAM 崩溃 | 每次只调整一类对象，执行打开/取消/关闭循环测试 |
| Web 拆分引入脚本顺序问题 | 页面启动失败 | 保持无构建器运行方式，增加模块加载测试 |
| CMake 整理遗漏源码或依赖 | 干净构建失败 | 每批使用全新构建目录验证 |
| 当前工作区包含未归属修改 | 覆盖或误提交用户内容 | P4-0 先分类，只暂存当前批次文件 |
| 重构演变为性能改写 | 范围失控 | 性能热点只记录到阶段五待办 |

## 18. 非目标

以下内容不纳入阶段四：

- 新增 DXF 实体类型或改变现有支持范围；
- Material、Section、Load、BC、Step、Job 等 FE 业务功能；
- 大规模批处理、并行解析或新的线程模型；
- 根据未经验证的 SDK 接口改写生产 FE 创建路径；
- Web 框架迁移、TypeScript 迁移或引入打包器；
- UI 视觉重设计；
- 修改曲线离散精度或节点合并算法；
- 没有基准数据支撑的性能微优化；
- 清理与当前职责无关的全部历史代码。

这些内容应分别进入产品功能阶段、阶段五性能优化或独立技术债任务。
