# 样例与测试数据

本文说明 DXF 样例的来源、分类、使用方式和完整性校验。若要选择一个输入文件开始调试，先阅读本页，再查看 [`../example/README.md`](../example/README.md) 或 [`../test/data/README.md`](../test/data/README.md)。

## 两层数据集

项目采用两层数据集，避免把几十 MB 的真实图纸全部复制进插件仓库：

1. **仓库内稳定集**：`example/` 中 28 个演示与集成样例，`test/data/` 中 9 个最小回归夹具。它们的路径受 C++、JavaScript 测试和人工验收流程依赖。
2. **外部完整集**：同一工作区中 OpenOLTranSim 的 `Community-plugins/io-plugins/DXFtoSam/dxf_test/`，共 55 个 DXF，用于更广的兼容性、压力和真实图纸测试。

外部完整集是测试资料来源，不是构建或运行时依赖。移动本项目目录后，插件仍可构建和运行。

## 映射与完整性

外部完整集的 `MANIFEST.csv` 记录类别、文件名、字节数、SHA-256、来源和仓库内对应路径。当前核对结果：

- 55 个外部 DXF 均与清单中的 SHA-256 相符；
- 清单中声明的 37 个仓库映射全部存在且哈希一致；
- 其中 28 个映射到 `example/`，9 个映射到 `test/data/`；
- `arc_half_circle.dxf` 对应 `example/half_circle_up.dxf`，`arc_partial.dxf` 对应 `example/part_circle_down.dxf`，文件名虽不同但内容一致。

新增或替换测试文件时，应同步更新 `MANIFEST.csv`，并重新校验字节数和 SHA-256。不要只按文件名判断是否重复。

## 建议执行顺序

1. 运行 `regression/`，快速验证历史缺陷。
2. 运行 `basic_element/`，检查各实体的解析与转换。
3. 运行 `block/` 和 `function/`，检查组合变换与资源预算。
4. 最后运行 `ship/`，记录真实大图的正确性、耗时、内存、取消和回滚行为。

每次结果至少记录：解析状态、各类实体数、跳过/失败数、展开后几何数、边界、耗时和峰值内存。需要跨版本精确比较时，使用[几何指纹](02-DXF解析与转换流程.md#几何指纹)而不是只比较“导入成功”。
