# 样例与测试数据

本文说明 DXF 样例的来源、分类、使用方式和完整性校验。若要选择一个输入文件开始调试，
先阅读本页，再查看 [`../example/README.md`](../example/README.md) 或
[`../tests/fixtures/dxf/README.md`](../tests/fixtures/dxf/README.md)。

## 唯一数据源

项目只维护一套 DXF：`tests/fixtures/dxf/` 中的 55 个唯一文件。C++ 测试、Node 测试、
几何基线、GUI 验收和教程都直接引用这里的分类文件。`example/` 只提供选择入口，不保存副本。

完整分类集已经随项目保存，但不是插件的构建或运行时依赖；普通编译不会读取这些大型
DXF。各文件的详细用途见 [`../tests/fixtures/dxf/README.md`](../tests/fixtures/dxf/README.md)。

## 导入完整性

从原 DXFtoSam 测试目录复制到本项目时已经逐文件核对数量、字节数和 SHA-256：

- 源目录与 `tests/fixtures/dxf/` 均为 56 个文件，即 55 个 DXF 加 1 个 README；
- 两侧总大小均为 51099320 字节；
- 没有缺失文件或哈希不同文件；
- 项目内不存在内容相同的 DXF 副本。

新增或替换完整集文件时，应同步更新 `tests/fixtures/dxf/README.md` 中的分类和用途，并重新
核对文件数量、字节数和 SHA-256。不要只按文件名判断是否重复。

## 建议执行顺序

1. 运行 `regression/`，快速验证历史缺陷。
2. 运行 `basic_element/`，检查各实体的解析与转换。
3. 运行 `block/` 和 `function/`，检查组合变换与资源预算。
4. 最后运行 `ship/`，记录真实大图的正确性、耗时、内存、取消和回滚行为。

每次结果至少记录：解析状态、各类实体数、跳过/失败数、展开后几何数、边界、耗时和峰值内存。需要跨版本精确比较时，使用[几何指纹](02-DXF解析与转换流程.md#几何指纹)而不是只比较“导入成功”。
