# 构建、部署与测试

## 1. 已验证环境

| 项目 | 已验证配置 |
|---|---|
| 操作系统 | Windows x64 |
| 编译器 | Visual Studio 2017 / MSVC 19.16 |
| CMake | 4.4 |
| C++ | C++17 |
| Qt | SAMSDK 内的 Qt 5.12.6 |
| Python | SAM 内嵌 Python 2.7 |
| Node.js | 18 或更高 |
| 测试 | Google Test 1.15.2、Node 内置 assert |

SAM SDK 和 Qt 库的 ABI 与工具集绑定，不能仅因为本机安装了更新的 Visual Studio 就随意
切换生成器。使用其他工具集前需要重新验证 SAM 加载和运行时依赖。

## 2. CMake 依赖

`3rdParty/` 用来存放实际第三方库内容，不存放额外的 CMake 检索脚本。根
`CMakeLists.txt` 将它加入 `CMAKE_PREFIX_PATH`，并按约定子目录寻找本地依赖。

解析优先级通常是 `-D变量`、对应的专用环境变量、`3rdParty/<依赖名>`、兼容回退
位置。spdlog 的 `VCPKG_ROOT` 属于兼容回退，因此排在本地 `3rdParty/spdlog` 之后：

| CMake 变量 | 环境变量 | 项目本地位置 | 回退位置 |
|---|---|---|---|
| `EXAMPLE1_3RDPARTY_ROOT` | 无 | `3rdParty` | 无 |
| `LIBS_SAM_ROOT` | `SAM_ROOT` | `3rdParty/SAM` | `../../SAM` |
| `LIBS_SAMSDK_ROOT` | `SAMSDK_ROOT` | `3rdParty/SAMSDK` | `../../OpenOLTranSim-main/SAMSDK` |
| `LIBDXFRW_ROOT` | `LIBDXFRW_ROOT` | `3rdParty/libdxfrw` | `../env/libdxfrw` |
| `SPDLOG_ROOT` | `SPDLOG_ROOT` | `3rdParty/spdlog` | `VCPKG_ROOT`，否则必须显式提供 |
| `LIBS_FEASOFT_ROOT` | `FEASOFT_ROOT` | 跟随 SAMSDK | 使用 SAMSDK |
| `SAM_OCCT_ROOT` | 无 | `3rdParty/OCCT` | 无，可用 `-D` 覆盖 |

libdxfrw 必须已有 `src/libdxfrw.h`、`build/Release/dxfrw.lib` 和 `dxfrw.dll`。spdlog
目录必须是已经安装过的 CMake package，包含 `share/spdlog/spdlogConfig.cmake` 或
`lib/cmake/spdlog/spdlogConfig.cmake`。

## 3. 全新配置和构建

```powershell
cmake -S . -B build -G "Visual Studio 15 2017" -A x64 `
  -DEXAMPLE1_BUILD_TESTS=ON `
  -DLIBS_SAM_ROOT="D:/path/to/SAM" `
  -DLIBS_SAMSDK_ROOT="D:/path/to/SAMSDK" `
  -DLIBDXFRW_ROOT="D:/path/to/libdxfrw" `
  -DSPDLOG_ROOT="D:/path/to/spdlog"

cmake --build build --config Release --parallel 4
```

如果本机无法访问 GoogleTest 仓库，可以复用已有源码：

```powershell
-DFETCHCONTENT_SOURCE_DIR_GOOGLETEST="D:/path/to/googletest"
```

不运行 C++ 测试时可以省略 `EXAMPLE1_BUILD_TESTS=ON`。可选 ContainerShip 模块默认关闭。

## 4. 构建产物

```text
bin/Release/Example1.pyd
bin/Release/SAM.Pre.Example1Toolset.dll
bin/Release/dxfrw.dll
bin/Release/spdlog.dll（名称由安装包决定）
```

CMake 会把 libdxfrw 和 spdlog 运行时复制到 `Example1.pyd` 同目录。部署插件后重启 SAM，
确认 `File → Import → DXF...` 和 `Tools → DXFimport log` 可见。

## 5. C++ 测试

```powershell
ctest --test-dir build -C Release --output-on-failure
```

当前注册 14 项：

```text
GeometryUtils, DxfData, ConversionEngine, Convert, FeConversionEngine,
Parser, DxfImportLogger, ImportTransaction, DxfImportValidation,
DxfImportMode, DxfImportLayers, DxfBlockExpansion,
DxfTransformedCurves, ImportBuildService
```

测试的运行时 PATH 由 CMake 目标位置推导，覆盖 Qt、spdlog、libdxfrw 和 OCCT DLL。

## 6. Node 测试

```powershell
npm.cmd run check
npm.cmd test
```

`check` 对 Server 和页面 JavaScript 执行语法检查。`test` 依次覆盖：

- Agent 工具；
- 标注识别；
- DXF 图层语义；
- Server 安全和真实路由；
- Server/Web 模块边界；
- API Key 生命周期；
- DXF 展开限制；
- Web 编辑器模块；
- 三份几何基线。

项目没有 npm 运行时依赖，因此不需要 `npm install`。
