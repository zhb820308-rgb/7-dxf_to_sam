# 测试覆盖分析报告

## 1. 报告范围

本文分析 `tests/` 目录中的自动化测试，按以下五个质量维度说明现有用例、覆盖范围和缺口：

1. 正确性测试；
2. 边界条件；
3. 回归保护；
4. 安全测试；
5. 集成测试。

本报告基于 2026-08-03 的工作区状态。需要注意：同一个用例可能同时属于多个维度，例如 BLOCK 展开数量限制既属于边界条件，也可以保护历史缺陷不再复发。

## 2. 总体结论

五个维度都有相应测试，但目前没有一个维度能够认定为完整覆盖。

| 维度 | 当前覆盖程度 | 是否完整 |
|---|---|---|
| 正确性测试 | 核心几何算法较高，产品级中等 | 否 |
| 边界条件 | 数值和资源预算较高 | 否 |
| 回归保护 | 最小回归完整，真实图纸不足 | 否 |
| 安全测试 | 本地服务主要安全边界较高 | 否 |
| 集成测试 | 组件级中等，系统级偏低 | 否 |

核心数学、DXF 数据模型、BLOCK/INSERT 展开、事务回滚和服务端安全边界测试质量较好。主要不足如下：

- 没有代码覆盖率和分支覆盖率报告，不能给出完整覆盖的客观百分比；
- 55 个 DXF 夹具中只有 23 个被自动化测试或基线脚本直接引用；
- `ship/` 下 13 个真实船舶文件没有直接进入自动化测试；
- 没有真实 SAM 宿主、真实浏览器和真实模型数据库端到端测试；
- C++ 测试依赖本地 `3rdParty/googletest`；仓库不上传第三方实际内容，首次构建前需要按说明放置。

## 9. 测试基础设施问题

### 9.1 C++17 传播问题（已修复）

生产目标通过 `CXX_STANDARD 17` 属性启用 C++17，但该目标属性不会自动传播给包含公共头文件的测试程序。默认配置编译 `DxfParser.h` 时会出现：

```text
error C2039: “optional”: 不是“std”的成员
class template optional is only available with C++17 or later
```

本轮审查在所有目标共同链接的 `ExampleProjectOptions` 中加入：

```cmake
target_compile_features(ExampleProjectOptions INTERFACE cxx_std_17)
```

这样 C++17 要求会传播到核心库、插件和包含公共头文件的测试目标。修复后，
不再需要额外传入 `CMAKE_CXX_STANDARD`，14 个测试程序均可正常构建。

### 9.2 GoogleTest 改为本地依赖（已修复）

原配置使用 `FetchContent` 从 Gitee 克隆 GoogleTest，首次构建会受网络状态影响。
现在 `tests/cpp/CMakeLists.txt` 固定从 `3rdParty/googletest` 加载 v1.15.2，
CMake 配置阶段不再访问网络。

由于仓库不上传第三方库的实际内容，开发者需要先按照 `3rdParty/README.md`
放置 GoogleTest。若目录缺失，CMake 会立即给出明确错误，而不会静默下载或长时间等待。

后续 CI 应在构建前恢复受控的第三方依赖缓存。

### 9.3 缺少覆盖率与运行时检查

当前未发现：

- C++ 行覆盖率和分支覆盖率；
- Node 覆盖率；
- 最低覆盖率门禁；
- AddressSanitizer、UBSan 等运行时检查；
- 自动执行全部测试的 CI 配置。

因此，现有测试全部通过只能证明已有断言覆盖的行为正常，不能证明所有生产分支均被执行。

## 10. 改进优先级

### P0：保持测试构建可复现

- 确保标准文档中的 CMake 命令能够直接构建全部测试；
- 在开发机和 CI 中按固定版本准备 `3rdParty/googletest`；
- 将测试配置和构建加入持续集成。

### P1：补足高价值回归与安全用例

- 为 Agent 的删除、完成、旋转和缩放操作增加测试；
- 为畸形 DXF、截断 DXF 和文件读取错误增加测试；
- 为路径穿越、超大请求体和畸形 JSON 增加安全测试；
- 为未引用的 32 个 DXF 建立最少的解析、统计和几何基线。

### P2：建立系统级集成测试

- 在真实 SAM 环境中加载 `Example1.pyd`；
- 验证实际模型数据库写入、回滚和重试；
- 使用真实浏览器执行导入、编辑和导出流程；
- 将大型船舶文件放入 nightly/stress 测试。

### P3：引入质量度量

- 生成 C++ 和 Node 覆盖率报告；
- 为关键模块设置分支覆盖率门槛；
- 记录大型图纸的处理时间和峰值内存；
- 增加 AddressSanitizer 或同类运行时检查配置。

## 11. 最终评价

现有测试不是简单的“成功路径测试”：它对非有限数值、预算限制、递归深度、取消、回滚失败、凭证泄露和响应流限制都有明确断言。核心算法测试具备较强的回归捕获能力。

但当前测试结论应限定为：

> 基础解析、几何转换、BLOCK/INSERT 展开、事务编排和本地服务主要安全边界在现有自动化用例下通过。

当前尚不能声明：

> 所有 DXF 文件、真实 SAM 导入链路、真实浏览器交互和全部安全风险均得到完整覆盖。
