## 4. Critical 问题

### C-01：服务端 API Key 可被发送到请求指定的外部地址

**状态：已修复（2026-08-01）。**

**维度：安全性**

**位置：**

- `server.js:38-49`
- `server.js:55-76`
- `server.js:573-601`
- `server.js:604-616`
- `server.js:817-830`

**证据：**

1. `allowLocalCors()` 只决定是否添加响应头，不会拒绝来自非本地 Origin 的请求。
2. POST 接口没有校验 `Content-Type`，跨站页面可以使用简单请求提交文本形式的 JSON；即使浏览器不允许读取响应，请求本身仍可能执行。
3. `api_key` 未提供时会回退到服务端 `OPENAI_API_KEY`。
4. `api_url` 完全来自请求体，只限制为 HTTPS 或本机 HTTP，没有可信主机限制。
5. `providerRequest()` 会把选中的 API Key 放入 `Authorization` 或 `x-api-key`，发送到该地址。

组合攻击路径：

```text
非本地网页向 127.0.0.1 服务提交请求
→ 请求省略 api_key
→ 请求把 api_url 指向攻击者 HTTPS 服务
→ 服务端读取 OPENAI_API_KEY
→ Authorization 请求发送到攻击者服务
```

**影响：** 服务端密钥泄露、产生未授权模型调用和费用。

**必须修复：**

- 对 `/api/agent/process` 真正拒绝不可信 Origin，而不只是省略 CORS 响应头。
- 要求 `Content-Type: application/json`。
- 为页面与 API 建立一次性或会话级 CSRF nonce。
- 当使用服务端环境变量密钥时，只允许服务端配置的固定端点或明确主机白名单。
- 用户自定义端点只能搭配用户在本次请求中显式提供的密钥，不能回退到服务端密钥。
- 重定向后再次验证目标地址，或禁止自动重定向。

**验证：**

- 非本地 Origin 请求返回 403，模拟提供商没有收到请求。
- `OPENAI_API_KEY` 已设置且请求自定义 `api_url` 时返回 400。
- 合法本地页面和固定官方端点仍可工作。

**实际修复与验证：**

- API 仅接受与监听端口一致的 loopback HTTP Origin；非本地或端口不一致的 Origin 返回 403。
- 页面先从 `/api/session` 获取随机 CSRF Token，POST 必须同时提供该 Token 和 `application/json`。
- 使用服务端环境变量密钥时忽略请求中的 `api_url`，仅使用服务端配置端点；自定义端点必须显式携带请求级密钥。
- 上游请求设置 `redirect: "error"`，避免凭据经重定向流向另一地址。
- `tests/server-security.test.js` 覆盖 Origin、Content-Type、CSRF、服务端密钥端点和提供商密钥隔离，测试通过。

### C-02：INSERT 阵列和嵌套展开没有资源预算

**状态：已修复（2026-08-01）。**

**维度：正确性、安全性、性能**

**位置：**

- `src/Example1/DxfParser.cpp:238-251`
- `src/Example1/DxfParser.cpp:266-279`
- `src/Example1/DxfParser.cpp:660-681`
- `page/dxf.js:91-100`
- `page/dxf.js:384-385`
- `page/dxf.js:474-485`

**证据：**

- C++ 直接使用 DXF 中的 `rowCount × colCount` 执行双层循环。
- 最大递归深度只能限制深度，不能限制每层阵列相乘形成的指数级输出。
- Web 端的行列数为普通 Number，没有整数上限，也没有输出实体总量上限。
- 两端均在展开过程中持续向容器追加实体或线段。

**影响：** 恶意或损坏 DXF 可以让 SAM 或浏览器长时间无响应、耗尽内存或崩溃。

**必须修复：**

- 引入统一的 `ExpansionBudget`，至少限制：块数、INSERT 数、单个阵列实例数、递归深度、展开实体总数、离散线段总数。
- 使用安全乘法检查 `rows × columns` 和嵌套累计数量。
- 超限时停止并返回结构化错误，不允许静默产生部分结果。
- C++ 与 Web 使用一致或有明确说明的上限。

**验证：**

- 超大行列数立即失败，不进入长循环。
- 多层嵌套阵列在预算边界内成功，越界时稳定失败。
- 失败后输出容器保持清空或明确的不可提交状态。

**实际修复与验证：**

- C++ 与 Web 均限制单个阵列和累计块实例为 100,000，使用除法先行的安全乘法检查，避免 `rows × columns` 溢出后再判断。
- 两端展开输出上限统一为 100,000；Web 额外验证行列数为正安全整数，嵌套深度上限为 8；C++ 保留既有深度 32 并把越界改为明确失败。
- C++ 超限后清空 `DxfData`、保持 invalid 并返回带 `limit` 的错误；Web 抛出代码为 `DXF_EXPANSION_LIMIT` 的异常，不返回部分模型。
- 新增 C++ 恶意 DXF 夹具以及 Web 正常阵列、超大阵列、非整数行列测试；Release 构建、Node 测试和 CTest 7/7 均通过。
- 三个阶段一 Web 基准几何指纹全部保持不变。

## 5. Required 问题

### R-01：嵌套非均匀缩放使用错误的分解参数组合

**维度：正确性、架构**

**位置：** `src/Example1/DxfParser.cpp:200-225`、`389-396`

源码把外层和内层缩放直接相乘、角度直接相加。源码注释已经明确说明该方法无法表示非均匀缩放、旋转、镜像组合产生的一般仿射变换。

**影响：** 嵌套块可以成功导入但坐标、方向或形状错误，属于静默数据错误。

**修复：** 用 4×4 或适合当前二维/三维需求的仿射矩阵表达每一级 INSERT，并通过矩阵乘法组合；阵列偏移也进入同一变换。

**验证：** 增加旋转叠加非均匀缩放、单轴镜像、多层嵌套和非零块基点的坐标级测试。

### R-02：块内曲线保留路径没有完整应用变换

**维度：正确性**

**位置：** `src/Example1/DxfParser.cpp:302-377`

具体问题：

- ARC 中心被变换，但起止角没有叠加 INSERT 的有效旋转；负统一缩放还会生成负半径。
- ELLIPSE 主轴向量只缩放，没有旋转。
- SPLINE 控制点和拟合点被变换，但起止切向量没有变换。
- LWPOLYLINE 顶点 Z 被变换，随后离散时又被 `constZ` 覆盖；当前 `constZ` 没有包含插入平移和块基点变换。

**影响：** 旋转块、负缩放块和非零 Z 块中的曲线可能错误或被静默丢弃。

**修复：** 以统一仿射变换处理点、方向向量和方向性；只有能证明类型在该变换下保持不变时才保留原曲线，否则先离散再变换。

**验证：** 对每种曲线检查首尾坐标、方向、包围盒和镜像结果。

### R-03：忽略图层对 INSERT 及块内图层继承不生效

**维度：正确性、架构**

**位置：**

- `src/Example1/DxfParser.cpp:35-39`
- `src/Example1/DxfParser.cpp:660-681`
- `src/Example1/DxfData.h:9-18`

`addInsert()` 没有调用图层过滤；`InsertInfo` 也没有保存 INSERT 图层。块内 layer 0 应继承 INSERT 图层，但当前扁平数据模型无法表达该规则。

**影响：** 用户选择忽略某图层后，该图层上的 INSERT 仍可能完整导入。

**修复：** 在原始实体和 INSERT 模型中保留图层；展开时实现 layer 0 继承，再对有效图层执行过滤。

**验证：** 增加普通实体、INSERT、块内 layer 0 和块内显式图层四类过滤测试。

### R-04：FE 椭圆转换破坏相对主轴向量

**维度：正确性**

**位置：** `src/Example1/FeConversionEngine.cpp:130-146`

`DxfEllipse::majorAxisEnd()` 在数据模型中是相对中心的向量，但代码先对它应用基点平移，再减去已平移的中心：

```text
(majorVector + base) - (center + base) = majorVector - center
```

正确结果应保持为 `majorVector`。中心不是原点时，当前 FE 椭圆的长轴长度和方向都会错误。

**修复：** 只平移椭圆中心，主轴向量保持不变；后续若支持旋转或缩放，应按向量规则变换。

**验证：** 使用非零中心、非轴对齐主轴和非零基点，比较 Sketch/FE 离散坐标。

### R-05：FE rollback 明确保留半成品 Part

**维度：正确性、数据完整性**

**位置：** `src/Example1/PythonFiniteElementBuilder.cpp:65-103`、`215-221`

Part 在 `beginImport()` 中创建；后续节点、单元、取消或显示失败时，`rollback()` 只把 `m_active` 设为 false，并明确记录 Part 可能残留。

**影响：** 模型中留下半成品 Part；同名 Part 会阻止重试，用户必须人工清理。

**修复：** 验证并封装 SAM 的删除 Part API；若无法安全删除，改为临时唯一名称创建，全部成功后再发布/重命名，并提供明确恢复流程。

**验证：** 节点批次失败、单元批次失败、用户取消和显示失败后，仓库中均无半成品目标 Part。

### R-06：角度归一化和段数计算对极端有限值不安全

**维度：正确性、安全性、性能**

**位置：** `src/Example1/GeometryUtils.cpp:22-40`、`103-110`

`normalizeSweep()` 使用 while 循环按 `2π` 反复增减。极大有限角度会执行海量循环；角度差溢出为 Inf 时，后续段数计算还可能把 Inf 转为 int。`calculateArcSegmentCount()` 在转换为 int 之后才执行 10000 上限裁剪。

**影响：** 畸形曲线可导致 CPU 长时间占用、未定义或实现相关的数值转换行为。

**修复：** 先验证所有中间值有限；用 `std::fmod` 常数时间归一化；在浮点域裁剪后再安全转换整数。

**验证：** 覆盖 DBL_MAX 附近角度、巨大半径、最小允许容差和溢出角度差。

### R-07：浏览器把 API Key 持久化到 localStorage

**维度：安全性**

**位置：** `page/app.js:835-866`

Agent 配置整体序列化，其中包含明文 `apiKey`。localStorage 没有过期时间，任何同源脚本都能读取。

**影响：** XSS、调试脚本、同源扩展代码或本机用户可以取得长期保存的密钥。

**修复：** 不持久化 API Key；仅保存在内存或使用会话级输入。默认优先使用服务端安全配置，并在 UI 明确说明密钥存储策略。

**验证：** 刷新页面后 Key 字段为空，localStorage 中不存在密钥内容。

### R-08：上游模型请求没有超时和响应体大小限制

**维度：可靠性、安全性、性能**

**位置：** `server.js:604-623`

`fetch()` 没有 AbortSignal；随后直接解析完整 JSON。慢速、无响应或返回巨大响应体的端点可以长期占用请求和内存。

**修复：** 增加连接/总超时、响应体上限和明确的 502/504 映射；超时后主动取消请求。

**验证：** 模拟不响应和超大响应的提供商，服务能在限定时间和内存内失败。

### R-09：解析成功判定会把无效实体计为有效输入

**维度：正确性**

**位置：**

- `src/Example1/DxfData.cpp:256-295`
- `src/Example1/DxfParser.cpp:719-734`

`DxfData::addLine()` 等方法不校验实体，仍会追加并增加统计；`parseFile()` 最终只检查 `entityCount() != 0`。只包含无效支持实体的 DXF 可以被标记为解析成功，但转换阶段又全部跳过。

**影响：** 解析状态、日志统计和最终导入结果相互矛盾。

**修复：** 明确原始实体、有效实体和拒绝实体三个统计；解析成功条件使用有效实体数量，并记录拒绝原因。

**验证：** 只含零长度线、零半径圆和非有限坐标的输入必须稳定失败并返回明确统计。

### R-10：DxfSpline 的公共合法性检查不完整

**维度：正确性、类型边界**

**位置：**

- `src/Example1/DxfData.cpp:372-390`
- `src/Example1/GeometryUtils.cpp:224-275`

`DxfSpline::isValid()` 只检查数量和切向量，没有验证控制点/拟合点有限、节点序列有限且单调、有理样条权重数量和值。下游对有理样条直接访问 `weights[i]` 并构造 OCCT 对象。

**影响：** 非解析器来源或经过异常变换的样条可能越界访问、触发 OCCT 异常或产生错误几何。

**修复：** 把完整不变量放到 `DxfSpline::isValid()` 或受控工厂中，Parser 只负责构造和记录诊断。

**验证：** 覆盖权重不足、非正权重、乱序节点、非有限控制点和错误 degree。

### R-11：解析测试不可移植且关键断言过弱

**维度：测试质量**

**位置：**

- `test/test_parser.cpp:28-29`
- `test/test_parser.cpp:83-247`
- `test/test_parser.cpp:372-405`

测试路径写死为当前开发机绝对路径。多项测试只检查 `> 0` 或转换成功，无法捕获坐标、角度、方向和包围盒错误；多文件测试遇到文件缺失还会 `continue`。

**修复：** 由 CMake 注入源码和测试数据目录；文件缺失直接失败；为高风险几何添加精确坐标或容差断言。

**验证：** 在不同工作目录运行 CTest；故意改变块旋转或 FE 椭圆公式时测试必须失败。

### R-12：Sketch commit/rollback 不是失败原子操作

**维度：正确性、架构**

**位置：** `src/Example1/SamBuilder.cpp:184-257`

`commit()` 先插入仓库并执行 `Replace()`，随后进行场景切换和重建；后续没有结构化错误检查或补偿操作。`rollback()` 只删除 factory、清理标志和计数，不撤销已发生的仓库变更，也没有明确草图所有权。

**影响：** 提交中途异常可能留下已插入但未正确显示或状态不完整的草图。

**修复：** 明确提交状态机和每一步所有权；仓库变更后发生失败时执行补偿删除，或把不可失败的显示刷新移出事务成功判定。

**验证：** 对仓库插入、Replace、场景获取和 PDO 重建分别注入失败，确认最终仓库状态和返回状态一致。

### O-06：前端图层统计为每层重复扫描全部实体

`page/app.js:362-368` 对每个图层分别 filter 全部点和线，复杂度约为 `O(图层数 × 实体数)`。大型图纸应在一次遍历中建立图层计数映射。
