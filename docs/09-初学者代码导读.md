# 从 C/Python 脚本到 DXF→SAM 插件：初学者代码导读

这篇文档面向“懂基础语法、写过 Python 脚本，但没有大型 C++/Qt/工业软件经验”的读者。
目标是让你能解释项目产物、完整调用顺序、每层存在的原因，以及如果从白纸重写应从哪里开始。

建议先完整读第 1～7 节，再打开代码按第 8 节下断点。遇到陌生 C++ 语法时查第 10 节，
不要一开始陷进 OCCT、SAM SDK 或日志模块的细节。

## 1. 先把名字说清楚：当前仓库不是 VTKToolset

当前活动 C++ 目标是：

- `Example1Toolset`：Qt/SAM 图形界面插件；
- `Example1`：DXF 解析、转换、SAM 构建及 Python 绑定模块。

源码中没有名为 `VTKToolset` 的类、CMake target 或目录，也没有直接链接 VTK。项目处理
样条时使用的是 **OCCT（Open CASCADE Technology）**。VTK 更侧重科学可视化和网格处理，
OCCT 更侧重 CAD 曲线曲面及几何建模；当前项目借助 OCCT 构造和离散 B 样条，最终显示由
SAM 自己的场景系统负责。

如果课程把作业统称为 “VTKToolset”，答辩时可以说明：“课程语境里称 Toolset，当前仓库
实际产物名是 `SAM.Pre.Example1Toolset.dll`，核心几何依赖是 OCCT，代码里没有直接 VTK
调用。”不要把课程题目、插件目标名和第三方库名混成同一个东西。

## 2. 项目到底做什么

一句话概括：**读取船舶 CAD 的 DXF 图纸，检查并展开其中的几何，然后把它导入 SAM，
生成 Sketch 或有限元 Part。**

它有两套相互独立的产品入口：

| 入口 | 用户看到什么 | 核心输出 | 是否需要 SAM |
|---|---|---|---|
| C++/Qt 插件 | SAM 中的 `File → Import → DXF...` | Sketch 或 FE Part | 需要 |
| Web Studio | 浏览器中的 DXF 编辑器 | 浏览器工作副本、点线 DXF | 不需要 |

本教程主讲第一条 C++/Qt/SAM 链。Web 端在 `page/` 和 `server/` 中，使用 JavaScript
重新实现了解析与编辑，并不是 C++ 插件套了一层网页。

插件支持 `POINT`、`LINE`、`CIRCLE`、`ARC`、`LWPOLYLINE`、`ELLIPSE`、`SPLINE`
以及 `BLOCK/INSERT`。核心步骤是：

```text
DXF 文件
  → libdxfrw 读取文本
  → 项目自己的 DxfData
  → 展开 BLOCK/INSERT
  → 按用户公差离散复杂曲线
  ├─ Sketch：SamData(lines, circles) → SAM Sketch
  └─ FE：FeData(nodes, trusses) → SAM Part
```

“离散”是把连续曲线近似成很多小线段。公差越小，线段通常越多、形状越精确，耗时和
内存也越大。因此项目还设置输出数量预算，防止嵌套块阵列或极小公差产生数百万实体。

Sketch 保留原生直线和圆，其他复杂曲线离散为线，再用 SAM C++ Sketch SDK 写入。FE
把轮廓转为节点和二节点 Truss，用 SAM 内嵌 Python API 创建 Part；相距小于合并公差的
端点会复用同一节点，重复和零长度 Truss 会跳过。

## 3. SDK 是什么，本项目如何使用 SDK

SDK 是 **Software Development Kit（软件开发工具包）**。如果 SAM 是一座已经建好的工厂，
SDK 就是工厂向外部开发者提供的标准接口、零件规格和接线规则，让插件接入而不必修改
SAM 主程序源码。

| SDK 内容 | 本项目中的例子 | 用途 |
|---|---|---|
| 头文件 `.h` | `SAMToolsetGui.h`、`skcSketch.h` | 编译时声明类和函数 |
| 导入库 `.lib` | CMake 中的 `SAMGui`、`SAMKernel` | 链接时解析外部符号 |
| 运行库 `.dll` | SAM 安装目录内的库 | 运行时提供真正实现 |
| 文档/样例 | `docs/reference/*.pdf` | 查询调用约定和生命周期 |

头文件不是函数实现。编译器从头文件知道“传什么、返回什么”，真正函数体位于 SAM DLL；
CMake 的 `target_link_libraries` 告诉链接器到哪些库中寻找它。

### 3.1 ABI 为什么重要

ABI 可以粗略理解为二进制层面的“接头形状”，包括编译器如何排布类、传参数、修饰函数名
和分配内存。本项目依赖 SAMSDK 自带 Qt 5.12.6、SAM 内嵌 Python 2.7 和既有 MSVC ABI，
已验证 Visual Studio 2017。不能因为本机有更新的 VS、Qt 或 Python 就随意替换；源代码
可能编译通过，二进制接头仍可能不兼容，导致加载失败或运行崩溃。

`SAM V4.0 二次开发手册` 的 C++ 章节说明了 `.pyd`、`pyoModule`、模块初始化和 Fragment
注册；当前 `SAM Python 接口说明` 描述 `Part.createNode()`、`Part.Element(...,
elemShape=TRUSS)` 等 API。手册是参考，实际行为仍以当前源码、SDK 版本和测试为准。

## 4. 最终生成什么文件，它们是不是可执行文件

C++ 主线**不生成可双击启动的独立 `.exe`**。宿主可执行程序是 SAM，它负责进程入口、
Qt 事件循环、模型数据库和渲染。本项目生成两个由 SAM 加载的动态模块：

```text
bin/Release/Example1.pyd
bin/Release/SAM.Pre.Example1Toolset.dll
```

`SAM.Pre.Example1Toolset.dll` 是 Windows 动态库兼 Qt 插件，包含插件元信息、Toolset 注册、
菜单、对话框和日志查看器。SAM 通过 `SAMToolsetGuiInterface` 调用 `registerToolset()`。

`Example1.pyd` 是 Windows 原生 Python 扩展，本质仍是动态库；后缀告诉 Python 可 import
这个二进制模块。它导出 `initExample1`，注册模块 `Example1`、方法 `importDxf` 和示例
Fragment。因此 `import Example1` 加载的是 `Example1.pyd`，不是 `Example1.py`。

Windows 的 `.exe`、`.dll`、`.pyd` 都使用 PE/COFF 二进制格式，但入口不同：

- `.exe` 有进程入口，操作系统可直接创建进程；
- `.dll/.pyd` 由现有进程加载，不能当普通程序双击运行；
- `.lib` 是静态库或 DLL 导入库，主要供链接器使用；
- `.obj` 是单个 `.cpp` 编译后的中间目标；
- `.pdb` 保存断点和调用栈所需的调试符号。

运行时还需要 `dxfrw.dll`、spdlog DLL 和 SAM 自身依赖。遗漏依赖时 SAM 可能只报告模块
无法加载，而不是指出你写的某个 C++ 函数有错。

## 6. 为什么有那么多 `.h` 和 `.cpp`

- `.h` 声明类、结构体、函数签名和外部接口；
- `.cpp` 放函数体和本文件私有辅助函数；
- `#include` 在编译期提供声明，不等于 Python 运行时 import；
- 每个 `.cpp` 单独编译成 `.obj`，链接器再组合成 `.dll/.pyd`。

```cpp
// DxfParser.h：别人只需要知道怎样调用
class DxfParser {
public:
    bool parseFile(const QString& filePath, DxfData& outData, ...);
};

// DxfParser.cpp：真正校验并调用 libdxfrw
bool DxfParser::parseFile(const QString& filePath, DxfData& outData, ...) {
    // implementation
}
```

`DxfParser::parseFile` 中 `::` 表示函数属于 DxfParser。头文件保护宏或 `#pragma once`
防止声明重复包含。文件拆分的核心是隔离职责：解析器不应知道 Qt 对话框，转换器不应知道
SAM Repository，几何测试不应为了一段算法启动整个 SAM。

## 7. 点击一次“DXF...”后的完整调用链

```text
SAM 加载 SAM.Pre.Example1Toolset.dll
  → Example1ToolsetPlugin::registerToolset()
  → Example1ToolsetGui::createMenuItems()

用户点击 DXF...
  → Example1ToolsetGui::onImportDxf()
  → Example1Form::getFirstDialog()
  → new Example1DXFImportDialog

用户按确定
  → Example1DXFImportDialog::onCmdOk()
  → Qt 校验 + omuArguments 打包
  → SendCommand("import Example1")
  → SendCommand(Example1.importDxf(...))

SAM 内嵌 Python 加载 Example1.pyd
  → initExample1() / Example1Initialize()
  → Example1PytModule::importDxf()
  → args.Get(...) 生成 DxfImportRequest
  → runDxfImport(request)

核心主链
  → validateDxfImportRequest()
  → DxfParser::parseFile()
      → DxfInputFile::prepare()
      → dxfRW::read(&reader, true)
      → DxfReaderCallbacks::addLine/addCircle/...
      → expandDxfBlocks(...)
  ├─ Sketch：ConversionEngine → SamData → BuildService → SamBuilder
  └─ FE：FeConversionEngine → FeData → BuildService → PythonFiniteElementBuilder
```

数据会逐层换形，而不是同一个万能对象传到底：

```text
omuArguments → DxfImportRequest → DxfData → SamData/FeData
             → SAM Repository/Part → DxfImportOutcome
```

每层都能在越过下一个危险边界前检查完整性。Builder 真正修改 SAM 数据库，失败必须回滚，
因此解析器不能采用“读到一条就永久写一条”的简单做法。

事务状态如下：

```text
Idle → Preparing → Writing → Committing → Committed
                    └────────→ RollingBack → RolledBack
```

begin 前失败没有资源；create/commit 失败会补偿清理；Builder 析构时若仍拥有资源，会通过
RAII 再尝试 rollback。已提交数据不会因为后续视图刷新失败而被误删。

## 8. 应该按什么顺序读代码

### 8.1 第一遍：只追主干

1. `DxfData.h`：默认值、模式和一次导入有哪些输入？
2. `DxfImportApplication.cpp` 的 `runDxfImport()`：阶段和模式分叉在哪里？
3. `DxfParser.cpp` 的 `parseFile()`：第三方解析怎样变成 `DxfData`？
4. `SketchConversion.cpp` 的 `convert()`：Sketch 中间数据怎样产生？
5. `SketchConversion.cpp` 和 `FeConversion.cpp`：两种事务顺序为何分开？
6. `SketchImport.cpp` 的 Builder 方法：何时真正修改 SAM？
7. `Example1Module.cpp`：脚本参数怎样进入主链？
8. `Example1Toolset.cpp` 的 `onCmdOk()`：界面怎样调用模块？
9. `Example1Toolset.cpp`：插件注册和菜单怎样串起来？

这个顺序故意从业务中心向两端展开。第一次读成熟项目，先理解 `runDxfImport()` 比先研究
Qt 元对象宏更容易建立全局地图。

### 8.2 第二遍：让一条 LINE 走到底

```text
line.dxf
 → DxfReaderCallbacks::addLine
 → DxfData::addLine
 → ConversionEngine::convert
 → SamData::addLine
 → SamBuilder::createLines
 → skcGeomFactory::CreateLine
```

先不要混入圆弧、BLOCK、样条和 FE。讲清一条 LINE 后，依次增加 CIRCLE（原生保留）、
ARC（公差离散）、LWPOLYLINE bulge（一条输入产生多段输出）、BLOCK/INSERT（后置递归
展开），最后再读 FE 节点合并和 Python 批处理。

### 8.3 推荐断点

1. `Example1DXFImportDialog::onCmdOk`；
2. `Example1PytModule::importDxf`；
3. `runDxfImport`；
4. `DxfParser::parseFile`；
5. `DxfReaderCallbacks::addLine`；
6. `ConversionEngine::convert`；
7. `DxfImportBuildService::buildSamSketch`；
8. `SamBuilder::beginImport/createLines/commit`。

每到断点只观察当前参数、关键容器 `size()`、事务 state 和下一步调用。第一遍不要逐语句
进入 Qt、STL 或 SAM SDK 内部。

## 9. 如果从零开始写，第一文件和第一函数是什么

阅读顺序和编写顺序不同。从零实现应该先做一个极小竖切片：

> 给定基础图元夹具 `tests/fixtures/dxf/basic_element/multi_line_segments.dxf`，解析得到合法
> DxfLine；转换后仍为
> 一条线；使用假 Builder 时严格按 begin → createLines → createCircles → commit 调用。

### 9.1 第一个文件先写测试

在 `tests/cpp/test_dxf_data.cpp` 写最小期望（示意）：

```cpp
TEST(DxfLine, RejectsZeroLengthLine)
{
    const DxfPoint p(1.0, 2.0, 0.0);
    const DxfLine line(p, p);
    EXPECT_FALSE(line.isValid());
}
```

它先回答“什么叫正确”。若暂时不熟 Google Test，可以先当设计草稿，但最终应可运行。

### 9.2 第一个生产文件和函数

先写 `DxfData.h/.cpp` 中最小的 `DxfPoint`、`DxfLine`、`DxfData`。第一个有业务意义的
函数建议是：

```cpp
bool DxfLine::isValid() const;
```

它验证端点坐标有限并拒绝零长度线。理由是：它不依赖 SAM/Qt/libdxfrw，输入输出直观，
容易测试，后续解析和转换都依赖相同的合法性定义；你也会第一次实际使用 class、构造函数、
`const` 成员函数和对象组合。

### 9.3 从这一点长出整条链

1. **解析边界**：实现 `DxfReaderCallbacks::addLine()`，把 `DRW_Line` 转成 `DxfLine`；
   再实现只支持 LINE 的 `DxfParser::parseFile()`。
2. **纯转换**：定义 `SamData`，让 `ConversionEngine::convert()` 完成基点平移，但暂不调用
   SAM。先用单元测试核对坐标。
3. **事务接口**：定义 `ISamImportBuilder` 和 `DxfImportBuildService`。假 Builder 只记录调用；
   模拟 create 失败，确认一定 rollback 且不 commit。
4. **真实 SAM**：实现 `SamBuilder` 的 begin/createLines/commit/rollback，把 `DxfPoint`
   适配为 `gslPoint` 并用 `skcGeomFactory::CreateLine`。
5. **PYD 协议**：实现 `Example1PytModule::importDxf()` 和 `initExample1()`，让 SAM 能
   `import Example1` 并进入编排器。
6. **最后接 Qt**：按 Dialog → Form → ToolsetGui → ToolsetPlugin 的顺序给成熟用例增加
   图形入口。

接着按同一方法扩展：

```text
LINE → CIRCLE → ARC/LWPOLYLINE → ELLIPSE/SPLINE + OCCT
     → BLOCK/INSERT → POINT/节点/Truss → FE Builder
     → 进度、取消、日志、Unicode 路径 → 大图性能
```

每增加一种实体，都按“数据类型 → 外部回调 → 合法性测试 → 转换测试 → Builder/集成测试”
扩展。不要只在 UI 里手工成功一次就认为功能完成。

## 10. 常见 C++ 语法翻译

### 10.1 值、指针和引用

```cpp
DxfData data;                 // 值对象，离开作用域自动析构
DxfData* ptr = &data;         // 指针，可为空，用 ptr->clear()
DxfData& ref = data;          // 引用，必须绑定对象，用 ref.clear()
const DxfData& view = data;   // 只读引用，不复制大对象
```

看到裸指针，马上问：谁拥有它、谁 delete、能否为空。业务数据优先用值/引用；只有 SDK
规定、可能无对象、动态多态或跨生命周期时才需要指针。

### 10.2 `const`、继承和虚函数

```cpp
const QString& name() const;
```

左侧 const 表示返回只读引用；末尾 const 表示函数不修改当前对象。

```cpp
class DxfReaderCallbacks : public DRW_Interface {
    void addLine(const DRW_Line& data) override;
};
```

libdxfrw 虽持有 `DRW_Interface*`，运行时仍调用派生类版本，这就是动态多态。`override`
要求编译器核对签名，防止你自以为覆盖、实际写成另一个函数。

### 10.3 lambda 与 `auto`

```cpp
builder.setProgressCallback(
    [&progress](const QString& stage, int current, int total) {
        return progress.update(stage, current, total);
    });
```

lambda 是匿名函数；`[&progress]` 按引用捕获外层对象。Builder 只保存 `std::function`，
不必认识具体进度对话框。`auto` 则让编译器从右侧推导固定类型，不是 Python 动态类型。

### 10.4 `std::optional` 与移动语义

```cpp
const std::optional<DxfArc> arc = makeArc(data);
if (!arc) return;
use(*arc);
```

optional 明确表达“可能没有结果”。`std::move` 则允许 vector/string 把内部缓冲区所有权
交给新对象，避免深拷贝；被移动对象可析构，但不能再假定保留旧内容。

### 10.5 模板和 RAII

```cpp
template <typename Builder>
ImportBuildResult rollbackAfterFailure(Builder& builder, ...);
```

模板为具有所需操作的不同类型生成同一套函数。RAII 则把资源生命周期绑定到对象生命周期：
局部 Session 自动结束日志，Builder 析构时回滚未提交资源，Qt 父对象释放子控件，
`DxfInputFile` 析构时清理临时副本。函数中途 return/异常时也能清理。

## 11. Qt 界面和通信

```cpp
m_browseButton = new QPushButton(tr("Browse..."), dxfGroup);
```

`dxfGroup` 是父对象，父对象销毁时 Qt 自动销毁子控件。这不代表所有 C++ `new` 都不用
delete，而是 QObject 对象树的特定规则。

```cpp
connect(m_browseButton, SIGNAL(clicked()), this, SLOT(onBrowse()));
```

按钮发 `clicked` 信号，Qt 事件循环调用 `onBrowse` 槽。`Q_OBJECT` 让 moc 生成元信息，
CMake `AUTOMOC` 负责自动运行 moc。

GUI DLL 最后并不直接调用核心 C++：

```cpp
omuMethodCall mc("Example1", "importDxf", args);
SendCommand("import Example1");
SendCommand(mc);
```

它把操作交给 SAM 命令系统和内嵌 Python。参数名、模块名因此是跨边界协议，修改一端时
必须同步另一端并测试。

## 12. 不必死背设计模式，但要看懂职责

| 代码 | 常见名称 | 解决的问题 |
|---|---|---|
| `Example1PytModule` | Facade/Adapter | SAM 参数协议转项目请求 |
| `DxfReaderCallbacks` | Adapter/Callback | libdxfrw 类型转项目实体 |
| `ISamImportBuilder` | Strategy/Port | 隔离具体 SDK 写法，允许测试替身 |
| `DxfImportBuildService` | Application Service | 固定事务业务顺序 |
| `ImportTransaction` | State Machine | 防止非法顺序并跟踪所有权 |
| `Instance()` | Singleton | 访问 SAM 进程内唯一角色 |
| 析构回滚 | RAII | 所有退出路径都尝试清理 |

不要只说“用了 Builder 模式”。更有说服力的是：“服务只依赖小接口，测试可注入第二步
失败的假 Builder，验证一定 rollback，而无需启动 SAM。”

## 13. 自检问题

1. 为什么项目没有自己的 `main()`？
2. `.dll` 与 `.pyd` 分别被谁加载、负责什么？
3. GUI 参数在哪打包、在哪解包？
4. `DxfData`、`SamData`、`FeData` 有何区别？
5. 为什么解析时不立刻离散所有曲线？
6. libdxfrw 为什么要通过回调适配器？
7. BLOCK/INSERT 为什么后置展开？
8. Sketch 与 FE 为什么使用不同 Builder？
9. create 一半失败时，谁决定 rollback，谁真正清理？

讲不清某题时，只回到对应的一个文件和一个小 DXF 下断点，不要重读整个仓库。

## 14. 可用于答辩开场的 90 秒版本

> 这个项目把 DXF 船舶图纸导入 SAM，可输出 Sketch 或由节点和 Truss 组成的有限元 Part。
> 它不生成独立 exe，而是生成 Qt Toolset DLL 和 Python 原生扩展 PYD，由 SAM 加载。GUI
> DLL 注册菜单并收集文件、基点、公差、图层和模式，再通过 SAM 命令系统调用
> `Example1.importDxf`。PYD 把参数转成 `DxfImportRequest` 交给编排器。编排器先校验，
> 再用 libdxfrw 回调解析成与 SDK 无关的 `DxfData`，展开 BLOCK/INSERT。Sketch 分支转成
> `SamData` 并用 SAM C++ Sketch API 提交；FE 分支转成 `FeData`，合并邻近节点后通过
> SAM 内嵌 Python API 批量创建 Part。写入由 Builder 接口和事务状态机管理，创建或提交
> 失败会回滚，避免半成品。分层让解析、几何算法和事务能够脱离 SAM 独立测试。
