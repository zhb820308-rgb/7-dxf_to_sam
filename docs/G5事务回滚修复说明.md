## 2. 统一事务状态

新增 `src/Example1/ImportTransaction.h`，由 FE 和 Sketch Builder 共享：

```text
Idle -> Preparing -> Writing -> Committing -> Committed
                    \-> RollingBack -> RolledBack
```

事务记录 Builder 是否仍拥有待清理资源。回滚成功后再次调用不会重复删除；清理
失败时保持 `RollingBack` 和资源所有权，允许下一次调用重试；已提交资源禁止回滚。

## 3. R-05：FE 半成品 Part 清理

`PythonFiniteElementBuilder` 在创建 Part 前登记资源所有权。Part 创建命令、节点
批次、Truss 批次、用户取消或显示阶段失败后，调用方和析构兜底都会进入回滚。

回滚执行：

1. 通过 C++ Part Repository 查询目标 Part。
2. 若存在，执行 `del mdb.models[modelName].parts[partName]`。
3. 再次查询 Repository，只有确认目标不存在才将事务置为 `RolledBack`。
4. 查询、删除或验证失败时返回明确错误并保留可重试状态。

因此清理成功后，同一 Part 名称可以立即重新导入。

## 4. R-12：Sketch 原子提交

`SamBuilder` 现在区分三类状态：内存草图、Repository 草图和场景显示对象。

- Repository 的 `Insert()` 返回值必须成功。
- `basBasis::Replace()` 是事务提交边界；异常时返回失败。
- 提交失败后的 rollback 从最新 MDB 中删除同名草图、执行 `Replace()`，并再次
  Fetch 验证草图确实不存在。
- Repository 提交成功后事务立即进入 `Committed`。
- Undo、场景映射、PDO 重建和视图刷新移到提交之后；其异常只记录显示警告，
  不把已持久化且完整的草图误报为提交失败。
- Builder 析构时仍持有未提交资源会自动回滚。
