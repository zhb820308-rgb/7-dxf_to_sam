## 2. 阶段目标

阶段五只优化经过测量确认的真实热点，在保持 DXF 几何、SAM 对象、取消回滚和外部接口不变的前提下，降低大型图纸导入耗时与峰值内存，并建立可重复执行的性能回归方法。

本阶段的完成标准不是“代码看起来更快”，而是：

1. 优化前后使用相同机器、输入、配置和测量方法；
2. 热点有分阶段数据证明；
3. 优化结果达到量化门槛；
4. 几何指纹、对象数量、包围盒和事务行为保持一致；
5. 自动化测试、干净构建和 SAM GUI 验收全部通过。

## 3. 范围与非目标

### 3.1 本阶段范围

- libdxfrw 解析、BLOCK/INSERT 展开和曲线离散耗时；
- Sketch 对象创建批次、进度更新和事件处理频率；
- FE 节点合并、Python 命令批次和 SAM 提交耗时；
- 大量实体日志格式化与输出；
- Web 画布重绘、大数组复制和 JSON 序列化；
- 峰值内存、完成后内存、取消响应和连续导入稳定性；
- 性能基准脚本、记录表和回归门禁。

### 3.2 不在本阶段处理

- 新增 DXF 实体类型或产品功能；
- 修改 Base Point、Tolerance、Ignore Layers 等产品语义；
- 为追求速度降低曲线精度、几何正确性或取消可靠性；
- 没有基准数据支持的大规模重写；
- Qtitan、Python 2.7 或 SAM SDK 升级；
- 将第三方编译警告与性能修改混入同一提交。

## 5. 统一测量规范

### 5.1 测试环境必须记录

```text
CPU / 内存 / 操作系统
SAM 版本 / Python 版本
插件提交和构建类型
DXF 文件 SHA-256 与大小
导入模式与 Profile
Base X/Y/Z、Tolerance、Ignore Layers
Sketch 进度间隔或 FE 批大小
SAM 工程初始状态
```

### 5.2 每次运行记录字段

```text
原始实体数
BLOCK / INSERT 数量
展开后实体数
离散后点、线数量
实际创建对象、节点、单元数量
解析耗时
转换耗时
SAM 创建耗时
总耗时
导入前、峰值、完成后内存
取消响应时间
最终包围盒
成功、失败或取消结果
```

### 5.3 采样方法

1. 使用 Release 构建并关闭无关高负载程序；
2. 每个场景连续执行 5 次；
3. 第一次结果单独保留，用于观察冷启动；
4. 后 4 次排序，取中间两个值的平均值作为稳定中位数；
5. 优化前后交替运行，避免系统温度和后台负载造成单向偏差；
6. 差异低于 10% 时视为噪声候选，至少再执行一组 5 次测试；
7. SAM 峰值内存使用同一工具、同一统计口径记录。

### 5.4 优化准入门槛

候选路径满足以下任一条件才进入代码修改：

- 占总耗时 20% 以上；
- 是最大单项耗时；
- 峰值内存主要由该路径产生；
- 导致明显 UI 卡顿或取消响应变慢；
- 大图规模增长时呈现不合理的超线性趋势。

### 5.5 单项通过门槛

- 热点阶段稳定中位数改善至少 15%，或总耗时改善至少 10%；
- 若没有达到门槛，应回退该优化或记录不采用原因；
- 非目标阶段耗时不得稳定回退超过 5%；
- 峰值内存不得回退超过 10%；
- 取消响应不得慢于基线；
- 几何指纹、SAM 数量、包围盒和创建顺序语义保持一致；
- 所有自动化测试必须通过。

## 6. 实施总流程

```text
P5-0 冻结环境与测试协议
  ↓
P5-1 建立端到端性能基线
  ↓
P5-2 定位并排序真实热点
  ↓
P5-3～P5-6 按热点选择性优化
```

P5-3～P5-6 是候选优化通道，不要求全部修改。没有达到准入门槛的通道应标记为“数据证明无需优化”，不得为了完成步骤而改代码。

### P5-1：采集 SAM 端到端基线

目标：补齐命令行测试无法获得的真实 SAM 性能数据。

测试矩阵：

| 输入                         | Profile   | Sketch | FE             | 重点指标           |
| ---------------------------- | --------- | ------ | -------------- | ------------------ |
| `block_test_minimal.dxf`   | Small     | 必测   | 必测           | 固定开销、精确数量 |
| `slock_spline_zhenlie.dxf` | Large     | 必测   | 必测           | 曲线、阵列、批处理 |
| `ship2_block_test.dxf`     | Unlimited | 必测   | 资源允许时必测 | 总耗时、内存、取消 |

工作内容：

1. 每个场景按统一规范执行 5 次；
2. 从日志记录解析、转换、创建和总耗时；
3. 记录导入前、峰值和完成后内存；
4. 在 10%、50%、90% 三个进度附近分别测量一次取消响应；
5. 记录连续导入 5 次后的耗时与内存变化；
6. 输出《P5-1 SAM 性能基线报告》。

通过标准：所有必测场景都有完整原始记录、中位数、范围、对象数量和内存数据，不以主观感受代替数据。

建议提交：

```text
docs(perf): record SAM import baseline
```

### P5-2：热点分解与优化决策

目标：用数据确定优化顺序，不直接修改算法。

工作内容：

1. 计算各阶段占总耗时比例；
2. 区分解析、展开、离散、FE 合并、命令生成、SAM 创建、日志和 UI 调度；
3. 对最热的两个路径补充更细粒度计时；
4. 检查计时本身是否明显改变运行结果；
5. 为候选项写出预期收益、正确性风险和回退方法；
6. 确定 P5-3～P5-6 中实际需要执行的通道。

建议优先级判定表：

| 热点证据                             | 优先通道 |
| ------------------------------------ | -------- |
| SAM Sketch 创建或 UI 调度占比最高    | P5-3     |
| FE Python/SAM 提交或节点合并占比最高 | P5-4     |
| 解析、BLOCK/INSERT、曲线离散占比最高 | P5-5     |
| Web 重绘、数组复制、序列化占比最高   | P5-6     |

通过标准：至少有一份火焰图、阶段计时或等效数据支持结论；没有热点时允许直接进入 P5-7，不实施推测性优化。

建议提交：

```text
docs(perf): identify import hotspots
```

### P5-3：Sketch 创建与 UI 调度优化（条件执行）

候选措施：

- 比较进度间隔 2000、5000、10000；
- 将进度刷新与取消检查解耦，避免增大批次后降低取消响应；
- 减少重复字符串格式化和跨 Qt/SAM 边界调用；
- 对可安全批量提交的对象使用批处理；
- 保持创建顺序、事务提交和回滚边界不变。

测试方法：

1. 阵列图和船体图各执行 5 次 Sketch；
2. 对比创建耗时、总耗时、峰值内存和取消响应；
3. 在每组参数下执行创建前取消、创建中取消和同名重试；
4. 核对对象数量、关键坐标、包围盒和既有对象。

通过标准：达到单项性能门槛，取消与回滚无回退；否则恢复默认 5000 或回退修改。

建议提交：

```text
perf(sketch): reduce creation overhead
```

### P5-4：FE 转换与 Python/SAM 提交优化（条件执行）

候选措施：

- 比较批大小 2000、5000、10000；
- 分别测量节点命令生成、节点创建、Truss 命令生成和 Truss 创建；
- 减少重复访问 `part.nodes`、重复格式化和不必要字符串复制；
- 检查 `FeData` 空间索引容量与实际节点数量的偏差；
- 保持节点合并容差、节点顺序、Truss 连接和事务回滚不变。

测试方法：

1. 三份文件均执行 FE，重点比较阵列图和船体图；
2. 每个批大小执行 5 次并记录 Python 命令大小；
3. 核对节点数、Truss 数、连接关系和包围盒；
4. 在节点阶段和单元阶段分别取消；
5. 验证取消后无残留并可用同名 Part 重试。

通过标准：选择综合耗时、内存和取消响应最优的批大小，而不是只选择耗时最短值。

建议提交：

```text
perf(fe): tune SAM submission batches
```

### P5-5：解析、块展开与曲线离散优化（条件执行）

候选措施：

- 减少 BLOCK/INSERT 递归展开中的临时容器和重复复制；
- 依据实际输出数量改善安全的 `reserve` 提示；
- 检查曲线离散点数组的重复分配；
- 对超预算阵列增加不改变错误语义的提前估算；
- 避免重复计算稳定不变的变换或数值参数。

禁止事项：

- 不改变容差含义；
- 不改变曲线采样结果；
- 不改变递归、阵列和输出预算错误；
- 不通过减少输出实体换取速度。

测试方法：

```powershell
npm.cmd run test:geometry-baseline
ctest --test-dir build_stage5 -C Release --output-on-failure
```

另需执行 BLOCK/INSERT、变换曲线、预算边界和超限快速失败专项测试。

通过标准：几何指纹完全一致，热点耗时达到门槛，超限输入不得增加时间或内存风险。

建议提交：

```text
perf(dxf): reduce expansion allocations
```

### P5-6：Web 与 Node 大图性能优化（条件执行）

候选措施：

- 避免几何大数组的无意义复制；
- 减少重复 JSON 序列化；
- 合并无效的画布重绘；
- 将视口变化与几何重建分离；
- 保持 Agent 原图基线、工作副本和撤销语义不变。

测试方法：

1. 三份 DXF 每份运行 5 次解析与离散；
2. 记录加载、离散、首次绘制、缩放和平移耗时；
3. 重复执行选择、撤销、恢复原图和导出；
4. 运行全部 Node 测试和几何基线；
5. 浏览器中确认无卡死、白屏或状态污染。

通过标准：稳定中位数达到门槛，几何指纹和编辑器状态语义完全一致。

建议提交：

```text
perf(web): reduce large drawing copies
```

### P5-7：内存、取消与连续运行稳定性

目标：确认局部提速没有换来资源泄漏或较差的交互响应。

工作内容：

1. 对阵列图和船体图连续导入 10 次；
2. 分别测试 Sketch、FE、成功、失败和取消；
3. 记录每次导入前、峰值和完成后内存；
4. 检查进度窗口、回调、日志线程和上次参数是否残留；
5. 比较第 1 次与第 10 次的稳定内存和耗时；
6. 使用同名对象重复取消和重试；
7. 确认既有 SAM 对象始终不受影响。

通过标准：

- 无崩溃、死锁、半成品或悬挂窗口；
- 完成后内存不呈持续单调增长；
- 第 10 次耗时没有超过基线调查阈值；
- 取消响应不慢于阶段五基线；
- 同名重试成功。

建议提交：

```text
test(perf): cover repeated import stability
```

## 8. 每批次协作与 Git 规则

沿用阶段四的小步流程：

1. 一次只执行一个 P5 批次；
2. 完成后先汇报修改内容、测量数据、风险和测试步骤；
3. 用户按报告完成验收；
4. 用户回复“通过”后，才精确暂存该批次文件；
5. 提交并推送阶段五分支；
6. 不使用 `git add .`，不混入当前工作区已有修改；
7. 性能代码与基准文档可以同批提交，但无关重构、功能和警告清理必须分开。

## 9. 风险控制

| 风险                 | 控制措施                                          |
| -------------------- | ------------------------------------------------- |
| 基准噪声导致错误结论 | 同机、同配置、5 次采样、前后交替、低于 10% 时复测 |
| 大批次降低取消响应   | 将取消检查与提交批次分离，同时记录响应时间        |
| 以减少精度换取速度   | 几何指纹、数量、包围盒和曲线专项测试作为硬门禁    |
| 优化增加峰值内存     | 每个候选方案同时记录峰值和完成后内存              |
| SAM SDK 调用不可回滚 | 保持事务边界，逐阶段取消并验证同名重试            |
| 多项优化无法定位收益 | 一次只改一个热点，一个批次一个主题                |
| 测量代码本身产生开销 | 对比启用与关闭详细计时，稳定后保留低开销指标      |
| 工作区已有修改混入   | 使用明确文件列表暂存并核对`git diff --cached`   |
