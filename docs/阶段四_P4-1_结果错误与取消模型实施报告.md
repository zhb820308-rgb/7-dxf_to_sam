# 阶段四 P4-1：结果、错误与取消模型实施报告

## 1. 实施结论

P4-1 已完成代码实现和自动化验证，当前状态为：

> 结构化结果模型、主错误与回滚错误分离、Sketch/FE Builder 统一状态语义及对应自动化测试均已完成；等待用户执行 SAM GUI 验收。未执行 Git 提交或推送。

本批次保持 `Example1.importDxf()` 的外部返回方式不变：

- 成功：返回创建对象数量；
- 失败：返回 `None`；
- 取消：返回 `None`。

## 2. 修改目标

P4-1 解决以下问题：

1. 应用层原来只能区分成功、失败和取消，无法确定失败发生在校验、解析、转换、创建还是提交阶段。
2. 创建失败后，如果 rollback 也失败，原始创建错误可能被 `RollbackFailed` 覆盖。
3. Sketch 和 FE 虽然都使用 `ImportBuildResult`，但真实 Builder 内部失败清理的返回语义仍有差异。
4. 日志文案和程序状态需要解耦，不能依靠错误字符串判断流程。

## 3. 主要实现

### 3.1 应用层导入状态

新增 `DxfImportOutcomeStatus`：

```cpp
Succeeded
Canceled
ValidationFailed
ParseFailed
ConvertFailed
BeginFailed
CreateFailed
CommitFailed
RollbackFailed
```

现在应用层能够明确判断导入在哪个阶段结束。

### 3.2 稳定错误码

`DxfImportErrorCode` 新增：

```cpp
BeginFailed
CreateFailed
CommitFailed
RollbackFailed
```

这些错误码拥有稳定的日志文本：

```text
BEGIN_FAILED
CREATE_FAILED
COMMIT_FAILED
ROLLBACK_FAILED
```

日志文本可以继续本地化或调整，但不会改变程序控制流。

### 3.3 回滚状态独立保存

`ImportBuildResult` 新增：

```cpp
rollbackAttempted
rollbackSucceeded
rollbackMessage
```

处理原则：

```text
创建失败 + 回滚成功
→ 主状态仍是 CreateFailed
→ rollbackSucceeded = true

创建失败 + 回滚失败
→ 主状态仍是 CreateFailed
→ rollbackSucceeded = false
→ rollbackMessage 保存清理错误
```

原始错误不再被回滚错误覆盖。

### 3.4 Sketch/FE 创建服务统一

`DxfImportBuildService` 对 Sketch 和 FE 使用同一规则：

```text
begin 失败
→ 立即返回，不创建

create 失败或取消
→ 立即 rollback，不执行后续 create/commit

commit 失败
→ rollback

rollback 失败
→ 保留主失败，同时单独记录 rollback 失败
```

### 3.5 真实 Builder 内部清理

修正 `SamBuilder::beginImport()` 和
`PythonFiniteElementBuilder::beginImport()` 的内部失败清理路径。

以前内部 rollback 失败时可能直接返回 `RollbackFailed`，丢失最初的
`BeginFailed`。现在两类 Builder 都保留：

- 原始 `BeginFailed`；
- 是否尝试 rollback；
- rollback 是否成功；
- rollback 失败信息。

### 3.6 编排器结果映射

`DxfImportOrchestrator` 现在为以下路径返回明确结果：

| 流程 | 应用状态 |
|---|---|
| 参数或模式错误 | `ValidationFailed` |
| DXF 读取/展开失败 | `ParseFailed` |
| Sketch/FE 转换失败 | `ConvertFailed` |
| Builder 初始化失败 | `BeginFailed` |
| 对象创建失败 | `CreateFailed` |
| 用户取消 | `Canceled` |
| 提交失败 | `CommitFailed` |
| 直接清理失败 | `RollbackFailed` |

如果 rollback 失败，日志中会额外记录：

```text
rollback_succeeded=false
rollback_error="..."
```

## 7. 代码审查结论

### Correctness

- 主错误不会被 rollback 错误覆盖。
- 失败或取消后不会继续执行后续 create/commit。
- Python API 返回兼容性保持不变。

### Readability

- 应用状态、Builder 状态和 rollback 状态职责明确。
- 状态判断不依赖日志字符串。

### Architecture

- Builder 接口允许无 SAM GUI 的确定性失败注入测试。
- 应用结果模型位于核心库，Python 入口只读取最终结果。

### Security

- 本批次未增加外部输入、网络能力、密钥或依赖。

### Performance

- 只增加少量状态字段和失败路径处理，正常导入算法与循环不变。

审查结论：未发现新的 Critical/Required 代码问题；SAM 真实生命周期仍需人工验收。
